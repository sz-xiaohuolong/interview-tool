# 面试练习室 · AI 技术面试助手

面向个人本地使用的文本技术面试工具。围绕 Java 后端、AI Agent 开发、自定义岗位、简历和项目进行动态追问，保存完整对话与结构化复盘。

## 环境与启动

需要 Java 21、Maven 3.9+、Node.js 22 LTS（22.12+）或 Node.js 24 LTS、npm。SQLite 驱动随 Maven 安装，无需单独安装数据库。

```bash
test -f .env.local || cp .env.example .env.local
# 编辑 .env.local 后启动
./scripts/dev.sh
```

首次启动会安装前端依赖并下载 Maven 依赖。打开 <http://127.0.0.1:5173>，后端监听 `127.0.0.1:8080`。终端 `Ctrl+C` 停止两项服务；日志在 `.runtime/backend.log` 和 `.runtime/frontend.log`。

全站共用一个工程：`./scripts/dev.sh` 启动 `backend/pom.xml` 和前端默认 `vite.config.ts`，无需指定版本 Profile 或专用前端配置。所有后端依赖、源码、资源和测试均在 `backend/`，版本文档继续在 `docs/vibe/releases/v1/`、`v2/`、`v3/`、`v4/`、`v5/` 归档。内部源码、类、页面和资源按业务职责组织，不按迭代版本分区。松耦合通过职责分包和接口实现，允许修改相关现有代码；只有明确需要灰度或并行版本时才拆分实现。

日常仍读取现有 `data/` 资料库及 `.env.local` 模型和 V2 配置。综合面试会话与公开知识缓存沿用 `data/v3/`，不迁移历史数据。内部代码已移除版本分区，旧API地址、数据库表名、JSON来源标签及浏览器草稿键继续兼容。默认端口为5173/8080，可通过 `WEB_PORT`、`PORT` 和 `API_PROXY_TARGET` 调整；不要同时启动两个后端读取同一资料库。版本专用启动、测试脚本及Playwright配置已删除，统一使用本文命令。

调整 Java 包结构后，先停止开发服务，再执行 `mvn -f backend/pom.xml clean` 清除旧 class，然后重新启动，避免旧包中的类残留并参与 Spring 扫描。

模型尚未配置时，可以先在 `.env.local` 显式设置 `LLM_PROVIDER=mock` 体验业务流程。页面、会话和报告都会标注“测试模式”。Mock 的题目、追问和评分只用于验证软件流程，不能视为能力评价。正式练习需使用 `openai` 模式。

## 模型配置

点击右上角模型状态可打开“模型配置”。全站共用一套当前连接，提供 OpenAI、DeepSeek 和自定义 OpenAI 兼容服务；可手填模型 ID、主动获取列表和测试 JSON 输出。保存后后续请求立即使用新配置，已发出的请求继续使用原快照。获取列表和测试由点击触发，保存不会调用模型。

界面配置保存在 `DATA_DIR/model-config.json`，文件权限为 0600，重启后继续使用。密钥不回显、不进入浏览器存储；更换服务商或服务地址后需重新填写。HTTP 地址仅支持本机回环服务，其他服务使用 HTTPS。关闭弹窗会丢弃未保存的草稿；“恢复启动配置”可回到启动时的环境配置。

`.env.local` 仅用于启动配置，已加入 Git 忽略，界面保存不会修改它。启动脚本会加载此文件；直接使用 Maven 启动时需要自行导出环境变量。修改启动配置后重启后端；若已保存界面配置，需点击恢复才会重新使用启动配置。

```dotenv
LLM_PROVIDER=openai
LLM_BASE_URL=https://api.openai.com/v1
LLM_API_KEY=你的密钥
LLM_MODEL=gpt-4o-mini
LLM_TIMEOUT_SECONDS=60
LLM_REASONING_EFFORT=
```

`LLM_BASE_URL` 是包含 `/v1` 的服务根地址，应用在其后请求 `/chat/completions`。模型需要支持聊天接口与 JSON 输出；可替换成兼容服务的地址、模型与密钥。模型名称必须使用服务商 API 的完整 ID，例如本次验证的 `gpt-6.1-sol`，不能使用 `6.1sol` 这样的简称。不要在变量等号两侧加空格；含空格或 shell 特殊字符的值使用单引号包裹。`.env.local` 由 Bash 加载，只使用自己编写、可信的配置文件。

资料保存在本机；开始真实面试、押题和复盘时，相关资料文本与对话会发送到你配置的模型服务。密钥通过本机接口提交给后端，接口响应不返回密钥。默认缺少 Key 会给出配置错误，不会自动切换到 Mock。

如果长对话复盘超过默认的 60 秒，可将 `LLM_TIMEOUT_SECONDS` 调整为 `180` 后重启。本次真实模型配置使用 180 秒；报告超时后可直接重试生成，已保存的回答无需重新提交。

`LLM_REASONING_EFFORT=high` 会向聊天接口传入 `reasoning_effort: "high"`，适用于支持该参数的推理模型；留空使用服务端默认值。当前本地 `gpt-6.1-sol` 已配置为 `high`，统一用于规划、出题、押题与复盘，这是启动默认值；界面中的高级配置可覆盖当前思考强度。综合面试可另设追问模型与强度，DeepSeek 追问关闭思考。仅选择模型服务支持的参数，连接检测不能代替真实面试质量验收。

## 使用流程

- **快速练习**：选择岗位和3/5/8道主问题，默认5题、初级；无需资料，准备后直接开始技术与工程场景问答。每道主问题最多追问两次，追问另计；可以提前结束并复盘。Agent 主题可多选；全选表示扩大抽查范围，不保证一场覆盖全部主题。工作台“本场知识依据”内显示已选范围，资料份数单独统计，实际考点覆盖在复盘查看。
- **综合面试**：点击“开始面试”或首页综合面试入口，选择岗位、职级及可选资料，准备并确认摘要后开考。可选不限时训练或计时实战，逐题提交回答。
- **简历押题**：在资料库上传 PDF、DOCX 或 Markdown 简历，再生成 10 道带依据与准备思路的题目。可以重新生成，或者选择一道题进行逐题模拟。
- **项目面试**：创建项目并填写背景、技术栈、个人职责，附加设计文档。面试覆盖整体理解、实现细节与假设场景权衡。
- **复盘**：主动结束或完成规划后查看逐题分析、原始对话与改进建议。综合面试提供阶段回顾、技术依据与项目矩阵；旧模式保留四维评价及原有报告。
- **继续练习**：首页和历史保留进行中的会话，刷新后从服务端恢复。模型失败时保留已提交回答，使用“重试”继续。

Agent岗位可在折叠设置中多选六类主题，选择未练优先或复习已练。复习池为空时先提示切换；数量不足时显示补新数量，确认后再开始。结束后的考点回顾区分新练／复习、是否作答，并可定位原始问题；考点记录不表示已经掌握。目录位于 `backend/src/main/resources/knowledge/agent-interview-topics.json`，当前六类各10项；场景由本项目编写，逐项保留官方／一手来源。

快速练习仍由智能面试生成问题：先选能力考点，再优先参考独立素材目录中的未用原题，缺少匹配或素材已用完时动态出题。当前[JavaBetter素材清单](backend/src/main/resources/knowledge/questions/README.md)含60道原题，映射31个考点，其余29项保留动态出题；不保存网站答案。复盘显示参考原题及链接，本场问答ID与素材ID分别记录，答题时不显示内部素材。技术参考资料最多并行6份，单请求10秒、整组11秒；失败提示“本次未获取到参考文档”或“已使用本地缓存”，展开“参考文档获取详情”可查看准确原因及缓存是否过期。

旧模式的 5 / 10 / 20 分钟是题数强度，分别约 3 / 5 / 8 道主问题，并非强制倒计时。综合面试两种模式均按 8 / 12 道主问题规划，默认8题，允许根据追问和阶段覆盖调整实际轮数；计时实战另选 20 / 30 / 45 分钟，默认30分钟，确认开考后开始服务端倒计时。旧模式的压力风格仍要求专业、克制，不进行人身评价。

综合面试可选择一个主项目或填写简述，正常经过开场介绍、项目深挖、岗位技术与场景、候选人反问。新建项目深挖及 综合面试的复盘提供七项项目证据矩阵，缺口可进入单题补练。作答支持打字和浏览器语音听写，识别后可以修改，再手动提交；应用不保存音频、不下载语音模型，浏览器可能在线处理语音。旧历史不会补算矩阵或计时。详细规则见下文“综合面试”和 [V3 行为规范](docs/vibe/releases/v3/SPEC.md)。

## 公开仓库源码面试

在资料库创建或编辑项目时，可选填写 `https://github.com/所有者/仓库`。仍需提供项目描述或资料；目前仅支持公开仓库，每场一个主项目、一个仓库，不需要 GitHub Token。

项目深挖与综合面试会在准备时读取默认分支并锁定本场 Commit。重试、刷新、继续和复盘保持该版本；更换项目或使用仓库新版本需新建面试。准备及答题页显示仓库、版本和读取状态，答题时只提示有源码依据；复盘可展开实际问题对应的文件、行号与核验片段。

全部读取失败时，显式重试或选择“仅用项目资料继续”；部分成功时保留有效证据并显示限制。未填写仓库时按原流程面试。GitMCP 提供搜索线索，GitHub REST 核验内容，模型只可调用受限只读工具；不会 Clone、运行或修改仓库。源码能说明仓库实现，不能证明个人贡献。

默认启用，可在启动配置设置 `SOURCE_ENABLED=false` 关闭后续探索；已关联场次会提示显式选择资料面试。源码探索可能额外调用真实模型，最多每次准备4轮；其用量单独保存在本场源码快照，当前主流程界面 Token 合计不包含这部分。公开源码与片段会发送到配置的模型服务；搜索词会发送到 GitMCP。

实现与限定验收见[V5验证记录](docs/vibe/releases/v5/VERIFICATION.md)。

## 综合面试

日常点击“开始面试”进入 `/interviews`，可在准备阶段选择简历、JD和主项目；旧场次、简历押题及项目深挖继续使用原接口。快速练习从 `/configure/quick` 进入，与综合面试共用 `/api/interviews` 和同一工作台；带 `trainingLinkId` 的关联训练保留原路径。接口失败会明确显示错误，不切换旧接口。首页和历史统一展示快速、综合及原项目/简历场次。

追问可单独配置 `INTERVIEW_FOLLOWUP_MODEL` 与 `INTERVIEW_FOLLOWUP_REASONING_EFFORT`，后者默认 `low`；未指定追问模型时使用全站模型配置。`DATA_DIR/v3/` 继续保存综合面试快照及知识缓存，现有 `v2_*` SQLite表继续使用，避免改变个人库。旧 `V2_ENABLED`、`V3_FAST_MODEL` 和 `V3_FAST_REASONING_EFFORT` 配置仍作兼容读取，新配置优先；缺口补练需要先准备训练资料库。

### 准备与回答

- 岗位与职级必填。简历、JD 可从原资料库选择，也可补充JD；可选择一个主项目或填写简述，无简历时仍可围绕真实项目面试。无任何资料和真实项目时明确显示通用基准及假设场景。
- 准备阶段显示排队、分析、检索与题目准备，通常目标1～3分钟，最多5分钟。可离开后从记录恢复。
- 开考前核对技术栈、职责和待澄清点；更正仅用于本场，重新准备后可直接确认开考。
- 提交答案立即进入思考状态。即时追问只复用本地证据；模型请求默认等待30秒，服务端整轮31秒截止。可通过 `INTERVIEW_FOLLOWUP_DEADLINE_MS` 调整整轮毫秒数（100～121000，模型请求最长120秒），旧 `app.v3.fast-deadline-ms` 仍兼容，新配置优先。未及时取得有效追问时，使用本题未问过的相关备用题并明确标记；无备用题时保留回答，提供重试或下一题。
- 复盘目标约3分钟，仅评价已答题。没有可核对的官方依据、来源过期或冲突时标记待核实。逐字引用的存在不自动证明模型判断正确，仍可打开原始来源核对。
- 每场至多128次模型尝试，累计声明输出上限400000 tokens；其中最后1次及6500输出声明额度预留给复盘，失败和显式重试也计数。界面显示模型服务实际返回的累计输入、输出及合计Token，缺失部分明确标记，不估算。
- 公开检索仅访问预置技术来源，不向搜索网站传简历、公司或项目原文。模型分析仍会把所选资料和回答发送给本机配置的模型服务。
- 原始资料与回答保存在本地。超长模型输入会明确节选并提示，原本场记录继续保留。服务重启后中断任务等待手动恢复，不自动重新调用模型。

### 项目、语音与实战

- 新综合面试依次经过开场介绍、项目深挖、岗位技术与场景、候选人反问；可以提前结束，复盘如实列出未完成阶段。两种模式共用计划8/12道主问题，默认8题；整场题量是准备目标，实际可因追问增加、因阶段充分覆盖减少，不强求答满。不限时训练没有倒计时，实战另选20/30/45分钟；旧场次沿用原规则。
- 计时实战可选20/30/45分钟，默认30。确认开考起计，阅读、思考、输入和校对计时；准备、模型生成、识别结果等待及复盘不计。刷新和后台不重置，没有主动暂停。接近尾声收敛追问，为后续阶段留出机会。
- 到点停止听写及新题，保留已确认和未确认的草稿供校对；最后一答必须手动提交，不自动提交或丢弃。正常关闭服务保存用时，重启不扣宕机时间；硬崩时最近未保存的片段可能少计。
- 项目深挖和综合面试的作答框都支持浏览器语音听写，识别最终文字后可编辑再提交。应用不存音频、不回放、不下载模型。浏览器可能使用在线识别服务；拒绝权限、识别错误或不支持时会提示，继续打字即可。首版实际识别以Chrome人工验收为准。
- 新建项目深挖及综合面试围绕唯一主项目生成七点证据矩阵：业务背景与指标、个人职责、调用链路、选型依据、异常处理、性能证据、妥协方案。每项展示已讲清、待补强或未覆盖，并附本场原问答；未覆盖不表示能力不足，无真实项目不生成经历矩阵。
- 点击缺口的“定向补练”生成一道结合主项目的新题，复用现有单题练习；返回原矩阵可查看后续结果。重复进入恢复已有案例，原场表现和报告保持原样；失败时显式重试。
- 矩阵、四阶段和计时只用于带`experienceVersion:1`的综合场次；快速练习不使用这三项。旧历史原样读取，不自动补算或增加模型调用。旧场次仍可使用语音输入。

### 综合复盘

新场次的复盘先展示本场作答量、四阶段、最多三条有原答证据的优势和优先改进，再展开项目矩阵与主问题/追问分组。回答是否讲清与技术依据是否核实分别显示；点击诊断定位原答，必要术语附中文解释。准备与查证警告可展开查看。

待补强的回答可生成结合本场岗位、项目及原答的一道新题，复用单题练习与结果回查；刷新恢复同一案例，失败需显式重试。补练不改原报告。无新版标识的旧历史沿用原展示，不自动重算或新增模型调用。

公开来源联网烟测需显式启用，不调用模型：

```bash
KNOWLEDGE_LIVE_TESTS=true JAVA_HOME="$(/usr/libexec/java_home -v 21)" \
  mvn -f backend/pom.xml -Dtest=KnowledgeLiveSmokeTest test
```

冻结需求、技术方案和历史证据分别见 [V3 行为规范](docs/vibe/releases/v3/SPEC.md)、[技术设计](docs/vibe/releases/v3/TECH_DESIGN.md) 和 [验证记录](docs/vibe/releases/v3/VERIFICATION.md)。

## 专业追问与固定评测

新建快速练习和综合面试在原追问调用内保存有限诊断：已覆盖考点、当前回答短引、待核实缺口、下一步目的和简短理由。服务端核对短引、关联回答身份，控制每题追问次数并阻止完全重复的模型追问；进行中只展示面试问题，结束复盘后可以展开查看当时观察。诊断可能有误，复盘仍须重新核对原答及技术来源。

固定24例及评测工具见 `evals/interview-agent/README.md`，包括原问题、回答、历史、官方参考片段、预期/禁止行为和人工评分规则。默认离线；真实调用须显式选择，先原策略6例、人工评分，再运行新策略对照。全批原/新最多96次请求，失败计数，无自动重试。软件测试与JSON结构通过不能证明面试专业性提升，本轮状态见 [V4验证记录](docs/vibe/releases/v4/VERIFICATION.md)。

## 资料与数据

- SQLite 文件：`data/interview.db`；上传文件：`data/uploads/`。使用 `DATA_DIR` 可指定其他目录。
- 默认单文件最大 5 MiB；支持文本 PDF、DOCX、Markdown、TXT，简历上传限制为 PDF/DOCX/Markdown。
- 单份提取文本最多保留 24000 字符，进入模型的材料上下文最多 30000 字符；超长资料会显示截断提示。
- 扫描图片 PDF 暂不提供 OCR，需要先转成可提取文本的文件。
- 修改或删除资料不会改变已开始面试的资料快照与历史报告。
- 备份时先停止服务，再备份整个 `data/` 目录；恢复时同样先停止服务。不要把含个人资料的数据库或上传目录提交到 Git。

资料列表由后端的 `DATA_DIR` 决定。日常启动默认使用原 `data/`；如果使用新的独立验收目录，页面会显示另一份资料库，原来的简历、JD 和历史不会自动出现在那里。发现空列表时，先核对访问端口和数据目录，不要重复上传或覆盖原目录。V2 测试目录不能替代日常资料入口；将原库用于 V2 前，应先完成备份并按启用说明显式升级。

## 架构

```text
浏览器 Vue 3 / TypeScript / Vue Router / Tailwind
  └─ 同源 /api → Spring Boot 3 / Java 21
       ├─ Controller：输入与 HTTP 交互
       ├─ Service：资料解析、规划、面试状态、押题、复盘
       ├─ Mapper：SQLite 与资料快照
       └─ LLM 客户端：OpenAI 兼容 HTTP / 显式 Mock
```

后端根包 `cn.interview` 只保留启动类；在现有职责层内按业务分包，面试规则和固定任务单独组织：

```text
backend/src/main/java/cn/interview/
  ├─ Application.java
  ├─ controller/   请求接收与 HTTP 响应
  │   └─ interview/、training/、material/、model/
  ├─ service/      业务用例与状态流转
  │   └─ interview/、training/、material/、knowledge/、model/
  ├─ domain/interview/  面试流程策略、阶段计时与输入预算
  ├─ task/         固定模型任务调度、处理接口与并发限制
  ├─ mapper/       SQLite 访问与启动前结构检查
  ├─ entity/       资料和文档数据对象
  ├─ dto/          层间传递的资料上下文
  ├─ client/       外部调用与显式测试替身
  │   └─ interview/、training/、transport/、model/、mock/
  ├─ validation/   模型输出校验
  ├─ config/       Spring 配置与请求边界
  ├─ exception/    业务异常与统一错误响应
  └─ common/       参数工具、标识、内容摘要与创建响应封装
```

现有服务直接使用具体类，暂不拆分 Service 接口与 ServiceImpl；JSON 接口沿用现有格式，后续出现独立响应对象时再建立 VO。测试按被测职责放入对应包，跨包测试夹具只保存在测试源码中。

前端页面位于 `src/pages/`，按 `home/`、`history/`、`interview/`、`training/`、`material/` 归类；组件位于 `src/components/`，按 `common/`、`layout/`、`interview/`、`training/`、`material/`、`model/` 归类。测试跟随页面或组件就近放置。业务客户端仍位于 `src/api/`，结构定义位于 `src/models/`；共用一个 App、启动入口和路由，页面地址保持兼容。

后端 `client/transport/OpenAiJsonClient` 统一模型传输，`service/interview/InterviewService` 负责综合面试，`FocusedInterviewService` 负责项目深挖、简历单题及相应历史场次。专项训练服务位于 `service/training/`；其中 `OperationService` 负责业务操作幂等与恢复记录，`task/ModelTaskRunner` 负责固定任务执行。`client/mock/` 仅在显式 Mock 模式下使用，不会因缺少密钥而自动启用。

提示词统一保存在 `backend/src/main/resources/prompts/`：`focused/` 用于项目与简历单题面试，`training/` 用于训练固定任务，`interview/` 用于综合面试与快速练习。服务端校验模型 JSON，强制追问上限与状态规则；回答包含请求 ID 和问题 ID，避免重复提交与过期页面写入。报告保存原始对话引用，区分明确错误、没有提到、资料不足。`DATA_DIR/v3/sessions/` 和 `DATA_DIR/v3/knowledge/` 保留为已有持久化路径，本次目录整理不迁移历史数据。

文档统一索引见 [DOCUMENT_MAP.md](DOCUMENT_MAP.md)。项目级文档包括[项目定位](docs/vibe/PROJECT.md)、[当前架构](docs/vibe/TECH_DESIGN.md)、[当前进度](docs/vibe/PROGRESS.md)与[决策记录](docs/vibe/DECISIONS.md)。V1 文档位于 `docs/vibe/releases/v1/`：[需求背景与范围](docs/vibe/releases/v1/PROJECT_BRIEF.md)、[完整产品行为与验收](docs/vibe/releases/v1/SPEC.md)、[实施计划](docs/vibe/releases/v1/IMPLEMENTATION_PLAN.md)、[实际验证记录](docs/vibe/releases/v1/VERIFICATION.md)。

## 专项训练资料库准备

专项训练目前提供“错题重练”和“项目经历”两个入口。错题复习与原题重练共用一个工作台，支持选题、草稿恢复、重新作答、变化对比和确认删除；删除只移除练习入口，原面试问答与报告保留。能力看板、岗位诊断和系统设计暂不展示导航，代码、数据及旧地址保留。正式版本仍是 V1，最新专项调整见 [V5 行为说明](docs/vibe/releases/v5/SPEC.md#专项训练收敛与错题重练工作台2026-10-21)。

专项训练、单题练习、JD、故事和设计训练使用同一应用中的业务模块。已有SQLite升级仍需要显式维护操作；`TRAINING_ENABLED` 是所选资料库的可用性配置，不用于选择不同版本实现。首次使用前先停服务，准备所选目录并保留完整备份：

```bash
python3 scripts/prepare-training.py --data-dir /absolute/path/to/data \
  --backup /absolute/path/to/data-backup --confirm-maintenance
```

备份必须是尚不存在的独立目录。脚本先检查已有结构和迁移校验和，不重写历史记录；原库已准备时不需重复执行。不要将空验收库替代日常资料目录。

开启后在“专项训练”中进入错题重练或项目经历。故事生成在模型调用前展示发送快照；重新作答保留原回答，删除需要确认，运行中的评估或对比结束前不可删除。真实练习使用本机配置的模型，测试记录明确标注 Mock。

完成所选目录的迁移后，在本机 `.env.local` 设置以下启动配置，再从项目根目录运行 `./scripts/dev.sh`：

```dotenv
DATA_DIR=/absolute/path/to/interview-tool/data
TRAINING_ENABLED=true
PORT=8080
API_PROXY_TARGET=http://127.0.0.1:8080
```

将示例路径替换为实际原资料目录。`DATA_DIR` 决定打开哪个 SQLite 文件，`TRAINING_ENABLED` 确认该资料库可用于专项训练；端口仅用于访问对应进程。启动脚本读取 `.env.local` 并导出变量；后端返回 `/api/training/status`，前端据此显示训练导航；所有页面仍由同一个App和router承载。修改配置后须重启服务并刷新页面。日常统一访问 `http://127.0.0.1:5173`；独立测试服务不必常驻。IDE 直接运行后端不会自动执行本项目脚本，需要配置同样的数据目录和训练资料库配置。

## 测试

```bash
# 后端测试、前端测试与生产构建
./scripts/test.sh

# 分开执行
mvn -f backend/pom.xml test
npm --prefix frontend test
npm --prefix frontend run build
```

浏览器验收使用独立临时数据库与明确标识的 Mock Provider，显式迁移合成库并启用 V2，关闭公开知识联网；统一构建后自动启动 4173 / 18080 两个测试服务，覆盖新旧场次与专项训练，结束后关闭并清理临时数据，不读取 `.env.local`。首次会安装 Chromium。

```bash
# 浏览器端到端：三种业务流程、刷新、快捷发送、报告与 390px 响应式
bash scripts/e2e.sh

# 仅验收专项训练：显式Mock、独立临时库
bash scripts/e2e.sh training.spec.ts training-keyboard.spec.ts

# 对已启动的 Mock 后端做 HTTP 验收（新增合成测试会话）
python3 scripts/smoke.py --output .evidence/mock-smoke.json

# 对已配置并启动的真实模型做相同验收；结果需额外判读语义质量
python3 scripts/smoke.py --real --output .evidence/real-smoke.json
```

HTTP 验收只创建合成资料，结束后删除自己创建的资料并保留验收会话，以便检查历史快照。真实模型的出题相关性、追问意义和评估质量需要单独核验，不能由 Mock 测试代替。当前实际证据见 [V1 验证记录](docs/vibe/releases/v1/VERIFICATION.md) 和 [V2 验证记录](docs/vibe/releases/v2/VERIFICATION.md)，两者各自保留适用输入与配置边界。

## 已知边界

仅面向本机单人使用，不包含登录、实时语音视频对话、音频保存回放、云端部署、向量检索或 GitHub 扫码。语音仅提供浏览器听写；不支持时仍可打字。请保持回环地址绑定。LLM 会受到服务商限流、超时与输出格式支持程度影响；失败会明确显示并保留可恢复状态。模型评价是练习参考，引用资料不能保证模型的每条技术判断都正确。没有足够回答时报告会说明样本不足，不凭空推断能力。
