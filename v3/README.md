# V3 本机使用与验收

V3 升级综合面试：选择目标岗位、职级及可选简历/JD和主项目，后台分析个人职责并预取公开技术资料，确认摘要后进行四阶段面试；支持不限时训练、计时实战和浏览器语音听写，结束后生成可回查来源的逐题复盘及项目证据矩阵。

## 启动

在仓库根目录执行：

```bash
./scripts/dev.sh
```

日常访问 `http://127.0.0.1:5173`，点击“开始面试”或首页“快速岗位面试”进入新版流程，也可直接访问 `http://127.0.0.1:5173/interview-v3`。后端为 `127.0.0.1:8080`。日志位于 `.runtime/backend.log` 和 `.runtime/frontend.log`，按 Ctrl+C 停止服务。

`./scripts/dev-v3.sh` 保留为独立入口，默认使用4173/18081。使用同一资料库前，请先停止日常服务，避免两个后端同时恢复同一会话；使用 `V3_DATA_DIR` 指定独立合成目录时可并行验收。独立入口日志位于 `.runtime/v3/`。

启动器读取根目录现有 `.env.local` 中的模型与 V2 配置，默认复用根目录 `data/` 中的资料。综合面试在 `data/v3/` 保存会话和公开知识缓存；缺口补练复用既有V2单题表，不新增表或自动迁移历史。原 V2 已开启时继续保留；新空库要使用缺口补练，须按原说明先准备 V2。

独立入口可选覆盖：`V3_PORT` 默认18081、`V3_WEB_PORT` 默认4173、`V3_DATA_DIR` 默认根目录data。日常入口沿用 `DATA_DIR`。写接口沿用原Origin限制，5173与4173均支持。

模型配置沿用 `LLM_PROVIDER`、`LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`、`LLM_REASONING_EFFORT`。追问可单独配置 `V3_FAST_MODEL` 与 `V3_FAST_REASONING_EFFORT`，后者默认low；未指定快模型时使用原模型。真实模型缺配置会明确报错。只有显式 `LLM_PROVIDER=mock` 才使用标记为Mock的测试输出。

## 使用与边界

- 岗位与职级必填。简历、JD 可从原资料库选择，也可补充JD；可选择一个主项目或填写简述，无简历时仍可围绕真实项目面试。无任何资料和真实项目时明确显示通用基准及假设场景。
- 准备阶段显示排队、分析、检索与题目准备，通常目标1～3分钟，最多5分钟。可离开后从记录恢复。
- 开考前核对技术栈、职责和待澄清点；更正仅用于本场，重新准备后可直接确认开考。
- 提交答案立即进入思考状态。即时追问只复用本地证据；服务端7秒截止，为轮询和渲染留出余量。未及时取得有效追问时，使用本题未问过的相关备用题并明确标记；无备用题时保留回答，提供重试或下一题。
- 复盘目标约3分钟，仅评价已答题。没有可核对的官方依据、来源过期或冲突时标记待核实。逐字引用的存在不自动证明模型判断正确，仍可打开原始来源核对。
- 每场至多32次模型尝试，累计声明输出上限100000 tokens；显式重试也计数。未自动重试，实际费用未知。
- 公开检索仅访问预置技术来源，不向搜索网站传简历、公司或项目原文。模型分析仍会把所选资料和回答发送给本机配置的模型服务。
- 原始资料与回答保存在本地。超长模型输入会明确节选并提示，原本场记录继续保留。服务重启后中断任务等待手动恢复，不自动重新调用模型。

## 新场次的项目、语音与实战

- 新综合面试依次经过开场介绍、项目深挖、岗位技术与场景、候选人反问；可以提前结束，复盘如实列出未完成阶段。两种模式共用计划8/12道主问题，默认8题；整场题量是准备目标，实际可因追问增加、因阶段充分覆盖减少，不强求答满。不限时训练没有倒计时，实战另选20/30/45分钟；旧场次沿用原规则。
- 计时实战可选20/30/45分钟，默认30。确认开考起计，阅读、思考、输入和校对计时；准备、模型生成、识别结果等待及复盘不计。刷新和后台不重置，没有主动暂停。接近尾声收敛追问，为后续阶段留出机会。
- 到点停止听写及新题，保留已确认和未确认的草稿供校对；最后一答必须手动提交，不自动提交或丢弃。正常关闭服务保存用时，重启不扣宕机时间；硬崩时最近未保存的片段可能少计。
- 项目深挖和综合面试的作答框都支持浏览器语音听写，识别最终文字后可编辑再提交。应用不存音频、不回放、不下载模型。浏览器可能使用在线识别服务；拒绝权限、识别错误或不支持时会提示，继续打字即可。首版实际识别以Chrome人工验收为准。
- 新建项目深挖及综合面试围绕唯一主项目生成七点证据矩阵：业务背景与指标、个人职责、调用链路、选型依据、异常处理、性能证据、妥协方案。每项展示已讲清、待补强或未覆盖，并附本场原问答；未覆盖不表示能力不足，无真实项目不生成经历矩阵。
- 点击缺口的“定向补练”生成一道结合主项目的新题，复用现有单题练习；返回原矩阵可查看后续结果。重复进入恢复已有案例，原场表现和报告保持原样；失败时显式重试。
- 矩阵、四阶段和计时只用于带`experienceVersion:1`的新场次；旧历史原样读取，不自动补算或增加模型调用。旧场次仍可使用语音输入。

## 工程验证

```bash
./scripts/test-v3.sh
```

它执行独立V3 Maven构建（包含原后端测试）、前端测试、Vue类型检查与独立V3构建，输出位于已忽略的 `frontend/dist/v3`。原启动与检查入口保持可用。

`./scripts/e2e-v3.sh` 在显式迁移的独立合成库上，使用V3后端和原有页面执行15项旧浏览器回归；模型显式为Mock，不读取.env.local。它占用4173/18080，执行前停止本次验收前端。V3新页面的真实模型浏览器结果另记在验证记录。

公开来源联网烟测需显式启用，不调用模型：

```bash
V3_LIVE_KNOWLEDGE=true JAVA_HOME="$(/usr/libexec/java_home -v21)" \
  mvn -f v3/pom.xml -Dtest=KnowledgeLiveSmokeTest test
```

冻结需求、设计与实际结果分别见 [行为规范](../docs/vibe/releases/v3/SPEC.md)、[技术设计](../docs/vibe/releases/v3/TECH_DESIGN.md)、[验证记录](../docs/vibe/releases/v3/VERIFICATION.md)。测试替身通过与真实模型质量分开记录，具体测时仅代表对应合成样本和当时服务状态。

## 追加式结构

`v3/pom.xml` 复用原Java源码、资源和测试作为输入，新增Spring AI模型接入、知识检索、会话编排、引用校验和独立持久化。2026-10-18获准修改相关现有源码，共享矩阵/补练服务放在原backend职责包，原backend可独立构建。前端增加 `src/v3` 与独立Vite配置，日常dev脚本已选择这套构建和配置；原综合面试入口由新增守卫导向V3，带V2训练关联的练习仍走原路径。简历押题与V2专项能力继续可用，项目深挖接入共享矩阵及语音。

## 新版综合复盘

新场次的复盘先展示本场作答量、四阶段、最多三条有原答证据的优势和优先改进，再展开项目矩阵与主问题/追问分组。回答是否讲清与技术依据是否核实分别显示；点击诊断定位原答，必要术语附中文解释。准备与查证警告可展开查看。

待补强的回答可生成结合本场岗位、项目及原答的一道新题，复用单题练习与结果回查；刷新恢复同一案例，失败需显式重试。补练不改原报告。无新版标识的旧历史沿用原展示，不自动重算或新增模型调用。
