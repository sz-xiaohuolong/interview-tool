## 4. 已采用的技术方案及理由

- 使用 Spring Boot 3.5、Java 21、JdbcTemplate + SQLite。直接读写 SQL，不用 JPA，减少适配 SQLite 和数据迁移的复杂度。首次启动创建表，不覆盖现有数据。
- 会话与报告保存为带版本信息的 JSON 快照，即保留当时内容的副本；核心资源分别存表。状态与消息在同一事务中保存，避免只保存了一半。删除资料不破坏历史快照。
- 大语言模型（LLM）使用 Java HttpClient 连接 OpenAI 兼容 `chat/completions`，一次返回完整 JSON，不使用流式输出。规划器、面试官、评估器和押题提示词分离；模型只建议下一步，服务端强制次数与状态边界。
- 后端保留已提交回答，失败标记中断；显式重试恢复同一轮。回答携带请求 ID 和最后问题 ID，分别防止重复记录和旧页面提交。单进程内按顺序处理变更，满足个人使用范围。
- PDFBox 提取文本 PDF；Apache POI 提取 DOCX；UTF-8 读取 Markdown/TXT。不引入 OCR。单文件最大 5 MiB，提取文本最多 24000 字符，模型材料上下文最多 30000 字符，截断明确提示。
- Vue 3 + TypeScript + Vite + Tailwind 4 + Vue Router，采用原生语义控件与轻量 Vue 图标库；不引入全局状态库。页面数据以服务端为准。
- 服务绑定 127.0.0.1，只接受本机连接。前端通过 Vite 代理访问 API；服务端检查写请求来源（Origin），默认不允许跨源访问。密钥仅从后端环境变量读取；日志不记录模型服务的响应正文或密钥。
- 模拟模型（Mock）必须显式配置，界面、会话与报告带标识；评分仅作测试示意，不表示真实能力。
- 目标时长不强制倒计时，提前结束后仅评估已有回答。无回答明确记录不可评价，不虚构表现。
