## 问题与目标

个人准备 Java 后端和大模型应用 / Agent 开发面试时，需要围绕岗位、真实简历和项目经历持续练习，并知道回答中的错误、遗漏与改进方向。V1 交付可每天在本机使用的文本面试训练工具，优先保证出题、动态追问和反馈质量，以及从开始练习到查看复盘的完整流程。

## 目标用户与核心场景

目标用户是准备技术面试的个人开发者，使用环境为本机单人、浏览器交互。

- 无资料时，选择岗位后完成一次快速面试并查看复盘。
- 有简历时，上传资料得到 10 道个性化押题，再选择单题练习。
- 有项目时，整理项目资料，经历整体理解、实现深挖、场景权衡三个层次的面试。
- 训练后，通过历史记录查看完整对话和薄弱项，继续未结束的会话或重新练习。

## 范围概要

V1 包含快速岗位面试、简历押题与单题练习、项目深度面试、统一复盘、资料管理，以及首页、配置、工作台、报告和历史页面。完整行为、状态、错误与验收由 [SPEC.md](SPEC.md) 维护。

## 本版不包含什么

- 产品功能：注册权限、支付、语音视频、GitHub 源码扫描、联网面经、复杂学习计划和社区。
- 使用形态：云部署和多用户服务。
- 额外基础设施：多代理（Multi-Agent）框架、向量检索、Redis、消息队列、微服务和 Kubernetes。

## 约束

- 仅供个人本地使用；文件和 SQLite 在本机保存，服务只监听本机回环地址，外部设备不能直接连接。
- 以普通服务编排和 OpenAI 兼容 HTTP 接口实现 AI 能力，提示词独立管理，后端控制状态与校验模型输出。
- 密钥只由后端本地配置读取；真实模型调用会将相关资料和对话发送至用户指定服务。
- 简历、JD、项目和回答均为不可信参考文本，不能覆盖面试规则，不能编造项目职责、指标或技术实现。
- 模拟模型（Mock）必须明确标识，只验证软件流程；真实模型质量单独验收。
- 不静默增加产品功能；新增范围需另行确认。代码仓库同步依据已有明确授权执行。

## 如何判断交付成功

| 目标 | 可观察结果 | 验收入口 |
|---|---|---|
| 本机可用 | 能启动并访问完整页面，运行与测试步骤可复现 | SPEC：AC01、AC11 |
| 三条训练路径 | 快速面试、简历押题和项目深挖均能完成从练习到复盘的流程 | SPEC：AC02～AC05 |
| 训练可持续 | 对话、报告、资料和押题持久保存；失败可恢复 | SPEC：AC06～AC08 |
| 事实和数据边界清楚 | 上传受限、截断可见、资料依据可核对，私密配置不泄露 | SPEC：AC09、AC10 |

实际结果见 [VERIFICATION.md](VERIFICATION.md)，本文只列目标，不记录测试结论。
