## 产品行为

### REQ01：快速岗位面试

- 无需上传资料即可开始，岗位支持 Java 后端、大模型应用 / Agent 开发和自定义岗位。
- 级别支持实习生、初级、中高级；目标时长为 5 / 10 / 20 分钟；风格为常规或压力面试，可补充技术栈或 JD 文本。
- 默认 Agent 开发、初级、10 分钟、常规面试。时长是规划目标，约对应 3 / 5 / 8 道主问题，不强制倒计时。
- 开始时规划本场问题，每次只提出一道题；根据用户真实回答决定追问或切题，每道主问题最多追问两次。
- 不机械重复预设题目；正式面试期间不主动泄露标准答案。用户可提前结束，自然完成或提前结束后进入统一复盘。

### REQ02：简历押题与单题练习

- 输入 PDF / DOCX / Markdown 简历、目标岗位及可选 JD，解析技术栈、项目经历、职责与亮点。
- 默认生成 10 道高优先级问题；每题包含问题、关联简历内容、知识点、准备优先级、推荐回答思路和可能追问，并标记潜在风险。
- 押题优先级是模型评估，不宣称企业真实题目、押题命中率；资料不充分时标记“需要补充”，不编造职责、技术指标或性能成果。
- 支持重新生成列表，或选择一道题开始逐题模拟。押题准备页可显示回答思路，正式面试工作台遵守不泄露答案的规则。

### REQ03：项目深度面试

- 支持手动填写项目名称、简介、技术栈、个人职责，附加 PDF / DOCX / Markdown / TXT 文档；项目可查看、编辑和删除。
- 面试覆盖 L1 整体理解（背景、价值、架构、职责、业务流程）、L2 实现深挖（模块、选型、数据流、异常机制、技术原理）、L3 场景权衡（并发、性能、故障、扩展、替代方案与局限）。
- 根据项目资料和本轮回答继续深入或切换主题，沿用每题最多两次追问的约束。
- 不将没有依据的实现当成事实；描述不一致或资料不足时可澄清，假设场景必须明确标识。复盘尽可能引用对应资料。
- 面试使用开始时的资料快照，之后编辑或删除资料不改变已开始会话与历史报告。

### REQ04：统一复盘与历史

- 报告展示岗位、模式、时间、题数、总体表现、主问题与相关追问、原始回答、逐题分析、推荐思路、知识解释、薄弱点与后续练习建议。
- 区分回答正确、明确答错、没有提到和资料不足无法判断；不能将遗漏直接当作错误，不能无依据补写用户表现。
- 技术准确性、理解深度、表达清晰度、追问应对能力分别采用 0～4 分并说明依据，不仅给无解释总分。没有回答时明确无法评价，不伪造评分。
- 报告可查看原始完整对话；历史支持列表与详情，薄弱项提供重新练习入口。

### REQ05：资料管理与本地保存

- 简历、项目和目标 JD 支持新增、查看、修改和删除；资料、文档、押题、会话和报告在本机持久保存。
- 简历上传限 PDF / DOCX / Markdown；项目文档另支持 TXT。拒绝不支持类型、空白或不可解析内容，并给出可理解提示。
- 沿用 V1 已实现边界：单文件最大 5 MiB，单份提取文本最多保留 24000 字符，进入模型的材料上下文最多 30000 字符；截断明确可见，不假装已完整阅读。
- 扫描图片 PDF 不提供 OCR，提示改用可提取文本的资料；删除资料不破坏历史快照。

### REQ06：页面、交互与错误恢复

- 首页包含三种训练入口、最近面试、保存资料、基于真实数据的练习情况；没有数据时显示空状态，不虚构统计。
- 配置页面按模式提供必要选项；工作台清楚区分面试官问题与用户回答，展示模式、进度、结束操作，支持多行输入、键盘快捷发送和加载状态。
- 避免重复提交；刷新后恢复已保存状态，历史可继续未结束会话。
- 模型调用失败保留已提交回答，明确显示原因并允许重试；报告失败保留原始对话，单独重试报告，不伪造成功。
- 缺少密钥、超时、限流、上游错误、非法 JSON 或结构均需可理解提示。缺少密钥不静默退回 Mock；显式 Mock 的页面、会话与报告标明测试模式。
- 过期页面提交和结束后继续回答均被拒绝。密钥、内部模型决策和未到达的参考答案不通过用户接口泄露。

## 用户如何操作，状态如何变化

```text
首页 → 配置快速面试 → 逐题回答与动态追问 → 结束 → 报告与历史 → 薄弱项练习
资料库 → 上传简历 → 生成押题 → 选择单题 → 面试与复盘
资料库 → 创建项目并添加文档 → 项目面试 L1/L2/L3 → 复盘
生成失败 → 显示错误并保留输入 → 重试原生成 → 继续面试或查看报告
刷新或重启 → 从持久化记录恢复 → 继续会话或重试中断生成
```

下表解释用户操作后会发生什么。大写标识为程序中的状态值，便于对照接口与日志；字段和 HTTP 细节见当前技术架构。

| 当前状态 | 操作或事件 | 结果与用户可见行为 |
|---|---|---|
| 待规划 CREATED | 规划与首问成功 / 失败 | 成功进入面试中 IN_PROGRESS；失败进入 FAILED，可重试规划 |
| 面试中 IN_PROGRESS | 有效回答 | 保存回答；追问、切题或结束 |
| 面试中 IN_PROGRESS | 后续问题生成失败 | 进入 INTERRUPTED，回答保留，重试同一轮 |
| 失败 FAILED / 中断 INTERRUPTED | 重试待处理生成成功 | 继续 IN_PROGRESS，或按流程结束 |
| 未结束会话 | 主动结束或完成题目 | 进入 COMPLETED，生成报告 |
| 已结束 COMPLETED | 再次发送回答 | 拒绝提交，原对话保持不变 |
| 报告生成中 GENERATING | 生成成功 / 失败 | 可查看 READY / 失败 FAILED；失败后可单独重试 |
| 有待处理生成 | 服务重启 | 会话或报告标为可恢复失败，避免永久加载 |

## 本版范围与数据安全

本版不包含注册权限、支付、语音视频、GitHub 源码扫描、联网面经、Multi-Agent 框架、向量检索、复杂学习计划、社区、云部署和多用户服务；不引入 Redis、消息队列、微服务或 Kubernetes。

服务仅监听本机回环地址，不允许其他来源的网页写入数据（跨源写入）。密钥和本地资料不提交仓库。简历、JD、项目文档和回答都是供模型参考的文本，其中的指令不能覆盖系统面试规则。

## 验收结论的适用范围

真实模型的出题相关性、追问意义与评估质量需使用已配置模型核验。Mock 自动化只验证编排、界面和持久化；模型评价用于练习参考，有限样本不证明所有输入的质量。
