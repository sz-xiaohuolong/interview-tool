### 隐私与适用范围

公开网络只接收资源清单中的固定 HTTPS URL，不接收简历、JD、用户回答或自由搜索词。重定向关闭，固定域名之外的地址、凭证 URL、端口、查询参数及非公开解析地址被拒绝；正文有 2 MiB 上限，每源外层最多等待 3 秒，每次最多六源。缓存独立存于 `DATA_DIR/v3/knowledge`，离线开关 `app.v3.knowledge.network-enabled=false` 只读已有缓存。来源错误、过期、未覆盖主题可通过同线程 `warnings()` 读取；调用方须将这些提示保存至本场。

本地检索采用有限词匹配与受控中英技术术语映射，并非语义向量召回；首批资料覆盖受控主题中的部分知识，不能证明所有个性化技术问题均有外部证据。正文仅保留前 10000 字符，匹配不到必须作为依据不足处理。上述编排随后已通过下面的片段一致性与真实链路补验；仍不能据此承诺所有技术问题都有相关片段。


### 知识片段一致性补验

后续审查发现：规划器接收的相关节选可能位于正文后部，而公共会话原先只保存资料开头；复盘按固定来源 ID 合并也会丢失新版本。已新增通用 `mergeSources`，按正文版本 ID 保留每阶段实际使用的 `excerpts` 集合、更新较新的获取元数据，并在复盘合并时重新按 48 小时计算 stale。准备、追问与复盘的模型输入片段均写回公共 sources，可逐字核对；正文变化产生另一版本 ID，旧问答引用保留。检索给模型时移除累计 excerpts，仅提供当前相关节选，避免快速追问携带无关历史长文。

新增真实 Service 编排测试 `KnowledgeEvidenceFlowTest`，使用本地合成公开资料与模型边界替身，先红复现“模型所见片段在公共快照中缺失”，修复后分别核对 PLAN、FOLLOWUP、REVIEW；其中追问使用了与准备不同的真实本地检索片段。知识单测新增版本合并、去重、历史过期与快速阶段输入裁剪检查。该验证只证明软件证据保存链，不代表真实模型训练效果。

## 失败测试与审查闭环

- 状态/HTTP初始红灯：新路由缺失时失败；完整资料准备、纠偏、确认、回答幂等、来源缺失复盘与历史读取随后通过。
- 模型边界：初始11项失败；扩展测试捕获8题重复后修复，最终16项通过。真实模式缺配置不切Mock；JSON/引用/超时/HTTP错误有明确边界。
- 并发恢复8项：短截止与迟到结果、旧轮定时器、新轮回答、取消竞态、服务重启不自动调用、次数与输出预算。准备/复盘预算文案曾2项失败，修复后8项通过；证据在 `/tmp/interview-v3-concurrency-{red,green}.log`。
- 独立审查发现三项P2：409后永久复用旧revision、移除已保存JD残留旧正文、仅引用JD绕过简历最低覆盖。三项均先红后绿并经原审查员复核，无剩余阻断问题。后两项后端红灯为8项中2失败、0错误，修复后8项全过；记录 `.runtime/v3/review-findings-{red,green}.log`。
- 公开所见片段未落盘、同版本刷新被丢弃、旧证据过期标记等问题均已用知识单测和真实Service编排补验；14项知识单测与1项片段链路集成通过。
