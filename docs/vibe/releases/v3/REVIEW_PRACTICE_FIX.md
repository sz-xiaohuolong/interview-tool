# 错题复习与原题重练修复记录

日期：2026-10-18。执行方式：vibe-workflow 有限范围路径，当前主代理独立执行。用户明确授权前端修复、文档沉淀、提交并同步远程。

## 目标与范围

修复 Review 卡片误建全新面试、继续入口重复建资源的问题；将 Practice 简化为进入即作答、提交即对比。保留待复习/已完成两个标签、置顶恢复和次级归档入口。

生产变更限定 `ReviewPage.vue`、`PracticePage.vue`，以及本次连续任务中报告整理入口的文案和复习列表链接。对应前端单测和浏览器用例同步调整。不提交其他本地功能、后端代码、数据库迁移、模型协议或启动配置，不包含部署。

上轮将 `CONFIRM → START → training-links → sessions` 当成“开始重练”的实现有误：新开的五分钟面试会丢失原题。原验收只证明了这条错误链路可运行，不能证明“原题二答”完成；该结论撤回，以本记录及当前代码为准。

## 实际行为

### Review：开始与继续分开

- 开始前读取复习项详情，查找同一 `questionIndex`、非追问且紧接着已有用户回答的 `ASSISTANT` 问题 ID；缺来源或主问题时明确报错，不猜测。
- 新发现的选择确认及开始状态在界面内部衔接，异议发现排除。随后完整分页查询来源案例，精确匹配来源、问题 ID 和模型模式；已有案例直接复用，否则调用 `POST /api/v2/practice-cases`，进入 `/practice/:caseId`。
- 继续入口从服务端案例及作答记录恢复，携带已有作答 ID；旧关联会话通过既有会话和训练来源只读接口查回，进入 `/sessions/:sessionId`，已结束但报告未就绪的记录进入原报告。
- “继续作答”仅导航，不发送创建请求。只有旧 `IN_PROGRESS` 标记、没有关联资源的条目重新显示在待复习中。
- 已完成按保存的作答/评估展示，不自动结束后台复习状态或绑定覆盖证据。显式重新安排复习仍回到待复习；归档和异议保留原文。

### Practice：自动准备与比较

- 完整分页查找草稿，恢复最新草稿；没有草稿时静默创建 `exposureDeclaration: UNKNOWN` 的新尝试。后端仍按实际解析提供记录确定 `effectiveExposure`。
- 已封存且评估失败、中断或进行中的回答优先恢复，沿用已有模型操作的查询和显式重试，页面刷新不自动重试模型。
- 题干突出展示；上一次回答、原报告诊断默认折叠，诊断展开时才通过原 reveal 接口读取。上下文、历次回答、评估组和比较历史集中到底部折叠区。
- 提交 READY 后，以 `ordinal=0` 原答和本次回答调用现有 `REEVALUATE_PAIR`。原答的历史协议未知，普通 `COMPARE` 只能得到没有结构化结果的 `TEXT_ONLY`，因此采用已有配对重评能力；原评估保留，不补造历史分数。
- 直接展示 `ComparisonResult` 的已修正、仍遗漏、新问题和建议；结果后的主要操作为“再练一次”“返回错题复习”。删除声明下拉、新建作答按钮、四个比较下拉及手动比较前置按钮。
- 比较失败保留已提交答案，重试比较不再次提交答案；已保存比较直接读取。结果地址携带作答 ID，刷新不新建草稿或重复调用模型。
- 应用按完整地址重建页面，因此比较保存后才替换结果地址；提交期间保留本页恢复标记，刷新时先核对服务端作答。再练时清理该标记，准备或恢复下一份草稿。
- STORY 来源首次没有原答时只展示单次反馈；后续可与上次已封存回答比较，不伪造历史原答。
