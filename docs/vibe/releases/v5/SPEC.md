# GitHub 公开仓库源码面试

2026-10-20。范围已确认，已实现；限定验证结果见[验证记录](VERIFICATION.md)。V5 仅表示文档归档，不创建独立工程，也不改变正式发布标签。

## 已冻结行为

沿用现有项目资料、项目深挖和综合面试。每份项目资料可选关联一个 GitHub 公开仓库，每场只使用一个主项目。仓库地址不能替代项目正文或附件，不增加首页入口、分支选择器或个人职责字段。

关联时核实公开状态与当前版本。新场准备时重新解析默认分支当前 Commit，随后立即保存；重试、刷新、继续及复盘均不得改变本场版本。编辑、解除资料关联不影响旧场快照。

准备阶段探索源码，允许模型调用限定仓库的只读工具；读取失败有明确状态与原因。全部不可用时必须显式选择“仅使用项目资料继续”或重试；部分可用时保留核验成功的证据并显示限制。未关联仓库时沿用原行为。

准备页显示仓库、版本与读取状态。答题期间只提示具有源码依据，不展示片段、文件链接或内部能力目标；复盘提供固定 Commit 的文件、起止行号与已核验片段。

源码证明仓库实现，不证明候选人的职责或成果。提问与追问引用独立证据身份；模型生成的路径、行号和内容不得直接成为事实。仓库文件、注释和文档全部作为不可信资料，不能改变工具权限或系统任务。

## 验收

1. 公开 Java 仓库接入成功；至少三个实际模型问题能对照固定版本的文件及内容。
2. 两条面试链路使用同一源码服务；综合四阶段、快速练习、简历押题及原项目流程保留。
3. 无仓库、错误地址、非公开或不存在、限流、第三方超时及模型不支持工具均有明确行为。
4. 不同项目、不同 Commit 的缓存及证据隔离；已有场次不受远程更新影响。
5. 刷新、重启、模型失败后原资料与已保存会话可恢复，重试不自动更换版本。
6. 外部请求限定 GitHub 与 GitMCP 固定服务，工具无法访问其他仓库、本机文件或执行代码。
7. 对响应、文件、请求和耗时设上限；过滤二进制、依赖、构建产物及明显敏感文件。
8. 真实源码证据与候选人回答证据分开；只有复盘能读取源码正文和内部分析。

不做私有仓库、OAuth、用户 Token 管理、Clone、Shell 执行、代码运行或修改、自定义 MCP、向量库、完整仓库 RAG、AST 索引、跨仓库分析或多 Agent 框架重构。

验证先使用隔离合成数据，再进行少量真实模型调用，逐次记录次数、用量、耗时和失败，不重试旧任务的停批请求。不迁移或覆盖日常个人资料，不提交、推送或部署。

验证覆盖目录完整性、实际服务落盘、去重与回退、追问继承、复盘及历史兼容、较慢资料与缓存失败详情、前端实际请求与浏览器展示。真实模型语义质量与软件结构验证分开记录，不恢复 V4 停批任务。
