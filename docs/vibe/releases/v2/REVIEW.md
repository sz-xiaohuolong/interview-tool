## 1. 建议怎样判断这版方案

V2 的价值在于把一场报告接到下一次具体练习，并保留能核对的原文。五项功能能沿用现有 Java、Vue、SQLite 和模型客户端，不需要更换技术栈。建议保留范围与实施顺序。

评审时的草案不适合直接开工，需要补齐五项约定：实际发送的资料必须与预览一致；更换模型重评必须能保存新评估组；数据库检查必须早于启动写入；关闭 V2 必须覆盖旧接口的关联分支；证据被质疑后必须撤下“当前支持”的标记。否则可能出现资料范围失真、无法恢复评估或历史依据误导用户的问题。

本报告保留当时的发现与推荐。用户随后批准完整 V2 及评审建议，推荐已归入 [SPEC.md](SPEC.md)、[TECH_DESIGN.md](TECH_DESIGN.md)、[IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md)，范围由 [PROJECT_BRIEF.md](PROJECT_BRIEF.md) 维护。五项功能已经实施，实际验证、受限校准失败及未覆盖质量见 [VERIFICATION.md](VERIFICATION.md)，不能把本次静态评审视为功能通过。

### E1：把资料预览绑定到实际输入

依据：[设计草案](TECH_DESIGN.md) 第 5.4、5.5、7.2 节目前分别描述资料 ID、故事生成和发送前展示范围，没有把预览结果绑定到执行请求。

建议增加固定业务接口 `POST /api/v2/jd-diagnostics/input-preparations`、`POST /api/v2/stories/{id}/input-preparations`。准备步骤只在本机整理资料，不调用模型，返回 `manifestId`、`manifestHash`、来源摘要、实际片段、范围和截断标记；记录复用固定类型的 operation，不增加通用资料平台。

执行请求携带上述 ID、摘要及 `requestId`。首次执行检查来源摘要和确认版本；资料已改或已删返回 409，模型调用数应为 0。预留成功后只使用确认过的快照，不按 ID 再读取新正文。同键重放优先返回原操作，不重新取资料或调用模型。后续测试需覆盖编辑、删除、截断变化和伪造摘要。

### E2：答案与评估组分开保存

依据：设计第 4.4 节要求换规则或模型时新建分组，第 4.2 节却把单份评估放在 attempt 中，第 5.3 节也没有建组接口。

建议增加 `v2_practice_evaluation_groups`，保存案例、1 或 2 个尝试 ID、冻结的规则与提示词正文及摘要、协议、状态、revision、实际模型元数据和至多两侧结果；每组对应一个 operation。attempt 保留原答并引用 `primaryGroupId`。这会将原 **13 张拟新增表调整为 14 张**，属于已采纳的技术修正。

初次提交建立初始组；`POST /api/v2/practice-cases/{id}/evaluation-groups` 明确使用服务端当前固定协议建新组，`GET /api/v2/practice-evaluation-groups/{id}` 找回结果。比较显式选择组 ID；`REEVALUATE_PAIR` 复用同一机制，历史 `IMPORTED` 原答只允许双侧配对重评，不新增单侧历史评分。

READY 组不能执行失败重试。失败组只有在冻结配置仍可执行时才可显式重试；旧配置不受支持时保留答案与旧失败，用户明确建立新组，不要求重新作答，也不静默换模型。规则和提示词正文仅保存在本地执行记录中，不向页面泄露隐藏规则；不保存密钥。不同题目或上下文不能因重评变成可比进步。

### E3、E6：检查必须早于写入，开关必须覆盖桥接

直接代码依据：[Store.java](../../../../backend/src/main/java/cn/interview/Store.java) 第 26～32 行在构造时创建目录、设置 WAL 并执行建表；[InterviewService.java](../../../../backend/src/main/java/cn/interview/InterviewService.java) 第 17 行启动恢复会写旧会话。独立放一个“检查 Bean”不能证明顺序正确。

建议把只读兼容检查放在全部业务写入之前。未知版本、校验和不一致或旧结构异常必须停止，逻辑表、记录和迁移台账不变；不承诺文件访问时间等物理属性逐字不变。全新空目录且 V2 关闭时保留 V1 初始化；开启但未迁移时明确失败，不隐式迁移。

V2 关闭时，带非空 `trainingLinkId` 的旧创建请求返回 `V2_DISABLED`，不退回普通会话创建；无来源请求保持 V1 行为。未迁移关闭、已迁移关闭两种情况均需验证：`/status` 安全返回 false，其他 V2 业务读写不触碰缺失表。应做完整应用启动及 HTTP 测试，不能只测迁移函数。

### E7：历史证据保留，当前支持可以失效

依据：SPEC 要求排除争议结论，设计第 7.1 节只写新增材料或训练事件提示来源变化，没有写已接受观察后来被质疑的传播规则。

建议按观察 ID 批量读取当前状态。旧诊断保留生成时证据和判词，同时明确其依赖已争议，不能继续作为当前有效支持。新确认和清单完成操作重新校验依赖，旧页面不能绕过。历史完成记录保留当时依据，当前要求显示争议；不自动重跑模型、不静默修改旧判词。新版诊断仍由用户发起并确认差异。

### E4、E5、E8：缺失证据和资源上限要能执行

- 比较证据分为 `QUOTE` 和 `ABSENCE_CHECK`。内容存在的一侧必须逐字引用；缺失侧保存固定检查点、全文快照 ID、摘要和范围。补全遗漏时旧侧可以是缺失检查，新侧必须有引用；两边都没有内容不能说已修正。结构校验只能证明引用合法，缺失判断是否合理仍要人工校准。
- 新 V2 模型执行名额建议初值为 1，立即拒绝超额请求，不排队。V2 发起的原规划桥接也占名额；不改变无来源 V1 的既有串行行为，也不声称新旧请求合计只有一个。重放先于抢名额；超额在封存答案、写 RUNNING 前返回 `503 MODEL_CAPACITY_BUSY`、`nextAction=RETRY_REQUEST`，保留草稿，显式再试。异常、超时及取消均释放名额；取消本机请求不能保证供应商停止计费。
- [LlmClient.java](../../../../backend/src/main/java/cn/interview/LlmClient.java) 第 43、48 行目前完整读取响应后才检查 2,000,000 字节；V2 `callDetailed` 应在读取中限长并取消超额响应，保留 V1 原调用行为。
- 新 V2 单条 payload 建议序列化 UTF-8 上限为 2 MiB，同时限制字段和数组。清单只保存最多 5 个当前活动项及必要摘要，动作历史复用 operation 分页；故事当前详情与版本历史分开；阶段保留每阶段 20 次提交限制，并限定反馈大小。超限拒绝新增，旧内容仍可读、可归档，不裁掉历史。初值待 S0/S6 用最大合法样本验证，不构成性能达标声明。

## 4. 产品、交互与维护方面的建议

### 4.1 先验证用户能否更容易完成下一次练习

产品评审的 5 项意见是：早期模型语义可行性、实际收益、确认负担、更简单的固定提示词加文本清单替代方案、技能目录覆盖。

建议在 S2 检查：能否找到明确下一步、完成一次重答、核对修正原文，以及修正错误模型结论的负担。V2 首次作答不应比 V1 增加跨页往返；来源与标签在同一详情页审阅，必要依据再展开，不增加全局确认或批量写入 API。实际动作数、耗时及收益目前未知。

固定技能目录应为每个 ID 写适用范围、排除范围和例子，用合成报告核对别名与误归类。无法归类就保留“未归类”；目录更新不自动改写历史，用户确认后追加归类事件。

### 4.2 补齐复习补证、历史找回与创建幂等

- `WAITING_EVIDENCE` 显示“待补证据”。`CONFIRM_EVIDENCE` 接受尝试或训练关联、发现 ID、版本和请求 ID，检查结果就绪、来源对应、无争议及 Mock 模式一致。仍未知就不改变状态；确认暴露错误或遗漏才转 DUE。
- 有支持证据且没有未处理发现时，允许显式 `RESOLVE_EVIDENCE` 结束待证事项，记录 `SUPPORT_CONFIRMED`；不计为修正错误或能力提升。无关、失败、旧版本和争议证据不能完成该动作。
- JD、短清单、阶段训练从原入口提供服务端分页历史；F2 从报告、复习项或故事找回案例及已有尝试，清除本页缓存后仍能继续。默认 20 条、最多 100 条，稳定游标；列表只含安全摘要，普通案例列表不带解析。
- 创建去重使用 `UNIQUE(kind, scope_key, request_id)`：根资源 scope 为 `LOCAL_USER`，子资源为父 ID；新生成的 `resource_id` 是结果，不能用作创建查重前提。同键同输入先重放，再检查当前 revision；异输入返回 409。首次响应丢失、客户端没有新资源 ID 时也能找回。

### 4.3 交互评审的 6 项建议

| 编号 | 推荐交互 | 后续验收 |
|---|---|---|
| D-01 | 待补证据与到期项分清，未来项显示下次日期；比较先呈现两次原文和条件 | 全未知、未来复习、只有一次尝试、三类可比性 |
| D-02 | F2/F5 即时保留本页草稿，显式“保存草稿”才保存到服务端；F4 使用“保存新版本” | 多标签、失败、丢响应、重开时保留两份文本，不覆盖封存答案 |
| D-03 | JD 超 12 条或 `hasMore` 时保留输入与选材，用户缩小后再提交 | 不自动重试，不用不完整结果覆盖旧诊断 |
| D-04 | 修改前序阶段前说明受影响阶段，保存后指向最早待处理处 | 旧产物可看，逐阶段“沿用此产物并重新评估”，迟到结果无效 |
| D-05 | 故事字段同区呈现事实依据、表达和确认 | 有源改写保留原来源；新增事实由本人补充为 USER_ASSERTION |
| D-06 | 延续视觉规范；窄屏按检查点成对比较、按要求显示双列状态、展开阶段列表 | 320/390/1440px、键盘、200% 缩放、焦点、文字状态及至少 44px 操作目标 |

保存状态应明确区分“仅本页”“已保存至本机服务”“保存失败”“版本冲突”。冲突提供复制本页、查看服务器版本及明确加载，不使用通用强制覆盖。已封存答案需新尝试，故事需新版本；阶段遵守当前 revision。浏览器离开提示不能承诺绝不丢失。

比较默认建议“原始回答→本次回答”；没有原答时选择最近两条，并允许手动选择。这是已采纳的偏好决定 D-T01。`TEXT_ONLY` 可以显式配对重评，`DIFFERENT_CONTEXT` 不提供该入口；解析提供情况始终单列。

### 4.4 开发体验评审的 5 项建议

1. **隔离启动**：S0 交付完整的前置环境、数据目录、维护迁移、启闭和合成 Mock 首次流程。[dev.sh](../../../../scripts/dev.sh) 会载入 `.env.local`，不能假设外层变量必然隔离真实配置。依赖满足后少于 5 分钟只是软目标；冷、热启动均未测。
2. **字段一致**：新增接口统一 `sourceKind`；`expectedVersion` 对应资源 revision，`expectedGeneration` 对应重试代次。创建、修改、重放、显式重试各有完整样例。
3. **错误能指导恢复**：保留 `code/message`，V2 按需增加 `resourceId/operationId/currentRevision/retryable/nextAction/helpKey/details`。区分版本过期、资源忙、非法状态、同键异输入、存储和模型失败。当前 [ApiAdvice.java](../../../../backend/src/main/java/cn/interview/ApiAdvice.java) 第 14 行仅输出 code/message，[api.ts](../../../../frontend/src/api.ts) 第 25～26 行也不会保留恢复字段，需窄幅扩展 V2，保留 V1 契约。
4. **按原职责归位**：审核后将本报告建议写回四份文档，尾部不堆积另一套规则。仅维护根 DOCUMENT_MAP，不创建第二地图或 TODO 事实源。
5. **固定模型默认并说明恢复**：复用现有 reasoning、timeout 配置；temperature=0.4 和 4500/6500 tokens 暂为服务端固定初值，记录实际参数。不新增任意参数面板；参数不支持或截断保留原文，配置改变后显式新建评估组。

`nextAction` 建议限定为 `LOAD_LATEST/WAIT_OPERATION/EDIT_INPUT/RETRY_OPERATION/RETRY_REQUEST/CREATE_EVALUATION_GROUP/CHECK_STORAGE/CHECK_CONFIGURATION/NONE`。帮助键仅指公开维护锚点；details 只含安全字段名、限值及枚举，不包含密钥、服务地址、路径、资料或供应商原响应。`retryable` 不触发自动模型重试。
