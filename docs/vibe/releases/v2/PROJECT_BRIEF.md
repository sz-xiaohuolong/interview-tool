本文说明用户价值、最小范围和已采纳决定。核对操作规则，阅读 [行为规范](SPEC.md)；核对技术方案，阅读 [技术设计](TECH_DESIGN.md)；核对任务顺序，阅读 [实施计划](IMPLEMENTATION_PLAN.md)。本目录 `TECH_DESIGN.md` 按用户要求命名，承担 V2 版本设计职责；实际接入同时登记到项目级当前架构。

## 3. 用户与核心问题

目标用户仍是准备 Java 后端、大模型应用 / Agent 开发岗位的个人开发者。V1 已能完成一场面试。V2 希望帮助用户回答五个后续问题：

1. 哪些问题需要再次练习？
2. 同一道题再答一次，具体改好了什么？
3. 对照目标岗位，哪些要求还缺少支持证据？
4. 怎样把真实经历讲清楚？
5. 怎样完整说明一个系统或 Agent 的设计方案及取舍？

## 4. 五项最小范围

| 功能 | 用户价值 | 建议的最小交付 | 本版边界 |
|---|---|---|---|
| F1 错题复习与能力档案 | 回到有来源的真实问题，安排下一次练习 | 按报告主问题提取错误、遗漏、未知候选；确认稳定技能标签；复习队列、自评及证据时间线；复用专项练习 | 不自动把未知判错，不做总能力分、排名或自适应记忆算法 |
| F2 同题二答与进步对照 | 检查建议是否落实到新回答 | 一次选一个原问题或追问；独立作答记录；固定题目、上下文及评分协议；原文与问题修正对照；记录解析暴露 | 不覆盖旧回答，不将不同上下文、评分协议或辅助条件的分差当成能力提升 |
| F3 JD 差距诊断与短冲刺 | 让岗位准备能追溯到要求及证据 | 从用户提供的 JD 提取最多 12 项要求；材料与训练证据分别展示；用户确认后建立最多 5 项的 7 天参考清单 | 不抓招聘网站、不安排日历通知、不输出录用概率；7 天不是强制截止时间 |
| F4 自我介绍与 STAR 故事库 | 复用真实经历，改善文本表达 | 两类模板：自我介绍、STAR；来源片段、用户补充事实、逐字段确认和版本；选择已确认版本进入单题文本练习 | 不生成虚构职责、成果和数字，不提供音频或口头表现判断 |
| F5 阶段式系统设计与 Agent 架构训练 | 产出完整方案并解释取舍 | 两个内置合成案例；五个固定阶段；结构化文本产物、阶段反馈、版本和恢复；服务端控制推进 | 不做图形白板、代码执行、任意流程编辑器或全新题库 |

F1～F5 是本次全部产品范围。SPEC 的跨功能要求仅保障这五项，不构成第六项产品。保留 V1 会话、报告、资料、押题与现有行为，不附带全站重构。

## 5. 建议实施顺序

1. **数据基础**：按已批准的迁移与回退边界，实现必要的版本、证据和幂等机制。
2. **F1 → F2**：先得到可追溯的复习来源，再完成独立重答、比较和更新复习记录的全流程。
3. **F3**：使用已有技能观察与练习来源关系，增加岗位要求和短清单。
4. **F4**：复用 F2 的单题作答与版本评估，只新增真实故事组织和文本表达规则。
5. **F5**：最后新增阶段状态与产物；复用基础设施，但不把 V1 的题号伪装成设计阶段。

实施计划将工作分为 S0～S7 八个交付单元，每个单元都应能单独验证。这是建议顺序，不是工期、投入或效果承诺；本次已按该顺序实施。

## 6. 未来如何判断这些功能有用

以下为成功指标；软件流程证据与尚未验证的真实质量、使用收益分别见验证记录。

| 目标 | 检查什么 | 验证方法 |
|---|---|---|
| 来源可追溯 | 每条被接受的复习、诊断、故事事实和比较结论都能定位原文；未知来源显式显示 | 构造含正常、缺失、截断与失效引用的合成资料，逐项核对；对应 V2-AC-101、V2-AC-302、V2-AC-402、V2-AC-605 |
| 重复操作无重复结果 | 同请求重放不新增回答、队列、事实或阶段产物；冲突请求明确拒绝 | 并发、断网响应丢失、进程重启的 API/DB 验证；对应 V2-AC-102、V2-AC-206、V2-AC-604 |
| 改善结论可判定 | 版本不一致不产生“进步”结论；有改善必须给出新旧原文证据 | 人工标注无改进、局部修正、修正且引入新错误、上下文变化样本；对应 V2-AC-204、V2-AC-205、V2-AC-608 |
| 五项都能完整使用 | 每项从入口到结果、失败恢复和再次打开均可完成 | 执行阶段分别做浏览器验收；V1 三条路径保留回归；对应各功能 AC 与 V2-AC-601、V2-AC-607 |
| 使用收益可观察 | 记录是否完成真实重答、哪些原问题被修正、哪些模型判断被用户纠正 | 后续由用户自愿提供反馈并人工复核本地记录；不新增遥测或许诺留存、录用效果 |

## 7. 已批准决定与理由

D01～D08 已随用户对完整 V2 与评审建议的批准采纳。每行说明基线及理由；后续改变产品范围或付费、数据边界仍需相应授权。

| 编号 | 推荐 | 理由与影响 |
|---|---|---|
| D01 范围与顺序 | 接受上述五项最小范围、F1→F2→F3→F4→F5 顺序 | 先完善从报告到下一次练习的流程，再复用证据与作答结构；不引入语音、真人互面、公司面经聚合、执行沙箱 |
| D02 复习与能力判定 | 候选经用户确认入队；只将同一来源主问题的发现放入同一个复习项；队列完成由用户明确选择；自评与模型观察分栏 | 防止错误合并与模型误判污染能力档案；完成练习不等于掌握技能；间隔先采用 1/3 天的明确选项 |
| D03 比较条件 | 协议一致才做同规则检查点对照，不新增单题总分；旧数据默认只看原文，可显式请求配对重评 | 旧报告没有模型和评分规则的完整历史信息，不能补造历史分数；查看解析后的结果标为辅助练习 |
| D04 JD 诊断 | 最多 12 条要求、5 个行动项；材料覆盖与训练验证分两列；清单更新需确认差异 | 避免关键词即能力证明及复杂日程平台；缩减过长 JD 时由用户明确选择范围 |
| D05 故事事实 | 模型只生成待确认草稿；逐字段确认；编辑产生版本；仅已确认版本进入表达练习 | 来源缺失时保留待补充；用户确认只是本人声明，不宣称外部核验 |
| D06 阶段推进 | 固定五阶段；必填产物齐备且反馈成功后由用户推进；低评价可确认后继续 | 服务端管状态，模型不代替推进；避免把低分变成无法结束的循环 |
| D07 数据与回退 | 新增 V2 表及版本台账，旧表不批量回写；停机备份整个数据目录；降级先保留新增表 | 历史兼容优先；快照包含个人文本，归档不等于删除；恢复旧备份会丢失备份后的写入，必须另行明确选择 |
| D08 模型调用与质量门槛 | 复用现有服务；显式操作才调用；失败不自动重试；真实模型校准另列审批和验证任务 | 保持成本与外部数据流可见；Mock 只证明流程，校准通过不能自动扩大产品范围或发布授权 |

## 8. 哪些事情还不能确定

- 假设单进程、本地单人仍满足使用需求；多标签页冲突必须处理，但不建设多人调度平台。
- 假设小型稳定技能目录足够覆盖首版 Java / Agent 练习；无法映射时保留“未归类”，不让模型自行创造 ID。
- 当前资料上下文以合并文本保存，缺少历史原文件的精确版本。V2 可以保存新快照，不能追溯生成不存在的旧映射。
- 真实存量数据数量、损坏记录、磁盘余量、迁移耗时，以及当前服务对新增输出格式的支持均待执行阶段核验。
- `DESIGN.md` 中“锁定脚本、路由”等条款属于已完成的 V1 纯表现层任务；V2 继承视觉规范，功能改动只能在新授权范围内进行，不延伸为全站重构。
- 本次编码授权已取得；真实模型支持、质量和用户收益仍须凭对应证据核验。不得将已写代码等同于完整版本验收。
