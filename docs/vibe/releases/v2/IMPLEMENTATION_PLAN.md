## 1. 先满足哪些条件，才能开始实施

批准需求：[PROJECT_BRIEF.md](PROJECT_BRIEF.md)、[SPEC.md](SPEC.md)。批准方案：[本目录 TECH_DESIGN.md](TECH_DESIGN.md)。真实架构仍为 [项目级 TECH_DESIGN.md](../../TECH_DESIGN.md)，当前 Release 仍为 V1。

本计划保留各切片的目标、测试接缝、风险与回退，并登记当前完成情况。用户已批准编码；合成目录迁移属于实现验证，真实个人库迁移、付费校准及发布分别核对授权。

阅读建议：先看第 2 节的交付顺序，核对是否能逐步获得可用功能；再看第 3 节的具体任务。第 4、5 节分别说明软件验收和真实模型质量校准，第 6 节用于逐项检查需求是否遗漏。

开工条件 G0 已满足：用户明确批准四文档及评审建议，采纳 D01～D08，并授权完整 V2 实施。真实个人数据库迁移、付费校准和发布，仍需按对应操作核对授权。

编号说明：S 是可独立验收的交付单元，T 是任务，REQ 是需求，AC 是验收标准，SEAM 是验证入口。幂等表示同一请求重复提交只保存一份有效结果；revision 是记录的修改版本，generation 是每次重试的代次。

## 3. 逐任务计划

### V2-T01：S0 数据、版本与防重复处理基础

- **需求与验收编号**：V2-REQ-06，V2-AC-601～606；V2-SEAM-06。G0 通过后仍先检查当前代码与待审设计是否一致。
- **实施位置（按新增约束调整）**：新增 V2Store/V2Operations/V2InputPreparations/V2OutputValidator、V2SchemaPreflight、装配类、迁移资源和维护脚本；V2_ENABLED 由新增配置读取，原 Store、application.properties 与模板不改。新增后端测试文件。
- **需要保存的数据**：按设计第 4、8 节创建 14 张 V2 表、索引和迁移台账；旧五类业务表与旧 payload 不批量回写。目录与固定规则版本先作为受控应用资源，不建后台管理页面。
- **先写会失败的测试**：重复迁移、校验和冲突、未知未来版本、事务中途失败、旧缺字段 JSON、同时更新相同 revision、同 requestId 异输入、存储异常、进程重启和旧 generation 迟到响应。
- **实现后怎样检查**：实现短事务与条件写、冻结输入、恢复为 INTERRUPTED、显式重试；用真实 SQLite 的合成库验证。模型使用可控替身，不接用户服务。
- **风险与回退**：Schema 与旧行为；关闭 V2 保留表，验证 V1 可读；事务失败应留下原库和原版本；毁损恢复只在副本演练。真实数据规模与停机窗口此时再核验。

### V2-T02：S1 报告导入、复习队列与技能档案

- **需求与验收编号**：V2-REQ-01，V2-AC-101～106；V2-SEAM-01；依赖 S0。
- **实施位置（按新增约束调整）**：新增 `ReviewService/ReviewStore`、控制器与 `skill-catalog.json`；新增 ReportTools 包装原 Report 的候选入口；新增 Review/Skills 页面；独立 v2/routes.ts 与 v2/types.ts；公共组件和样式仅按功能需要扩展。
- **需要保存的数据**：写 review_items、skill_events、operations；按主问题去重，模型原文与用户动作分开；不回写原 Report。
- **先写会失败的测试**：全未知、无回答、READY 缺字段、同一报告重复导入、新报告版本、别名/未知标签、不同题不能误合并、争议排除、归档恢复、1/3 天边界。时钟测试注入固定时间。
- **实现后怎样检查**：先做确定性导入及人工确认，不新增历史重评调用；前端验证候选→标签→队列→自评/异议，数据库验证原报告摘要不变。
- **风险与回退**：错误归类和误判扩散；保留原分类与来源等级，关闭复习入口保留所有记录。确认、归类和当前队列状态可根据记录重建，但不可删除原事件。

### V2-T03：S1 连接已有专项练习

- **需求与验收编号**：V2-REQ-01，V2-AC-105、V2-AC-107、V2-AC-601、V2-AC-604；V2-SEAM-01、V2-SEAM-06；依赖 V2-T02。
- **实施位置（按新增约束调整）**：新增 training-links 控制器与侧表读写；新增 TrainingLinkedInterviewService 同包子类，原 InterviewService 不改；新增 LinkedConfigure/ReportTools 传递并显示来源。原无关联调用、mode 与返回字段保持。
- **需要保存的数据**：侧表关联原 sessions；同事务预留 sessionId，模型在事务外规划。只为带有效关联的创建做持久去重。
- **先写会失败的测试**：两个标签同时创建、响应丢失后重放、同键异配置、链接不属于指定源、已用链接复用、规划失败后恢复、报告 READY 前不得完成复习。
- **实现后怎样检查**：沿用 `focus/role/level` 和既有规划器；完成原场面试后确认相应发现，再写来源事件。既有 Configure/Session/API 测试证明无来源路径仍成立。
- **风险与回退**：跨入 V1 的主要的会话创建衔接位置；关闭来源分支后原三条模式继续工作，已创建会话和报告不删除。

### V2-T04：S2 单题案例与独立尝试

- **需求与验收编号**：V2-REQ-02，V2-AC-201～203、V2-AC-206、V2-AC-208；V2-SEAM-02；依赖 S1。
- **实施位置（按新增约束调整）**：新增 Practice 服务、Store、API 与页面；新增 `practice_evaluator` 提示词和校验；新增 V2LlmClient 复用原配置，原 call 不改；报告/复习入口选具体问题。
- **需要保存的数据**：case、attempt、operation；原答只读导入，封存提交正文，保存规则及请求元数据。旧模型信息 UNKNOWN，不补造旧评分。
- **先写会失败的测试**：主问题/追问边界、泄漏目标答案至题面、资料改动不改变旧案例、提交后改正文、重复请求、解析暴露不能撤销、模型配置改变、Key 缺失、JSON 越界和评估重启。
- **实现后怎样检查**：读取新 DTO 不含参考答案；revealing 先写暴露再返回；浏览器检查草稿与新旧答案分开，失败只重试评估。单题结果不虚构追问表现。
- **风险与回退**：答案覆盖和比较基础污染；停用新尝试入口，原答/案例保留，V1 消息与报告字节不变。

### V2-T05：S2 比较、配对重评与复习结果

- **需求与验收编号**：V2-REQ-02，V2-AC-204、V2-AC-205、V2-AC-207；并覆盖 V2-AC-105、V2-AC-106；V2-SEAM-01、V2-SEAM-02；依赖 V2-T04。
- **实施位置（按新增约束调整）**：比较服务和 DTO、Comparison 页面、`practice_compare/practice_pair_evaluator` 提示词、规则指纹与引用校验；复习页新增有效结果关联。
- **需要保存的数据**：独立 comparison 结果，不覆盖两次历史评估；原答只读。完成复习写用户动作与所用评估，不把队列完成转换为能力标签。
- **先写会失败的测试**：题目/上下文/规则/服务/参数单项变化、原答模型未知、Mock/真实混用、辅助暴露、同答案不应“进步”、双侧引用非法、整题发现不属于所选追问。
- **实现后怎样检查**：先验证能否比较的条件，再接模型；用可控输出检验配对重评产生新结果、无改进与新增问题分别展示。真实结论质量留待 S7。
- **风险与回退**：伪进步结论；条件不满足回退到原文视图，保留全部尝试，隐藏不合格模型结论而不是伪造成功。

### V2-T06：S3 JD 诊断与短冲刺清单

- **需求与验收编号**：V2-REQ-03，V2-AC-301～306；V2-SEAM-03；依赖 S2。
- **实施位置（按新增约束调整）**：新增 JdDiagnostic/Sprint 业务模块、`jd_diagnostic` 提示词与校验、诊断与清单页面；新增页面内的选材和 LinkedConfigure 入口；复用 training-links。
- **需要保存的数据**：JD/材料/训练快照、稳定要求 ID、诊断版本、确认及清单历史。只按选定范围读取，不重新组织全部资料库。
- **先写会失败的测试**：空 JD、超过 12 条、缺材料、只有自评、争议证据、关键词误当验证、来源截断、超过 5 项、重复生成、新材料版本、已完成项被更新覆盖、同标签却不对应要求片段。
- **实现后怎样检查**：要求和两列证据→确认→清单→原专项训练→确认新证据→差异更新。清单动作分别测试补材料、训练和跳过；只点击入口不得完成。
- **风险与回退**：诊断误导与清单历史丢失；旧诊断固定保留，新版失败不替换；停用入口后原 JD 存储/输入/规划继续有效。

### V2-T07：S4 真实故事、版本确认与文本练习

- **需求与验收编号**：V2-REQ-04，V2-AC-401～406；V2-SEAM-04；依赖 S2，建议 S3 后进行。
- **实施位置（按新增约束调整）**：新增 Story 服务、Store、两种固定模板、Story 页面；`story_drafter` 提示词及字段校验；Practice 使用固定表达规则；新增训练导航进入故事库，原资料页面不改。
- **需要保存的数据**：story/version 与原文片段、用户事实、逐字段确认；练习持有确认版本快照。来源删除不级联删除已用版本。
- **先写会失败的测试**：无材料、未确认个人行动、数字/主体无出处、提示注入、模型草稿被误当本人事实、旧页确认新内容、修改后确认未失效、归档导致历史答案断链。
- **实现后怎样检查**：手动/生成草稿→逐字段确认→保存版本→两种不同问题的独立作答；模型失败不覆盖编辑；已展示故事按辅助准备标记。
- **风险与回退**：编造经历和确认范围不明；未确认阻止练习，旧版本只读保留；移除入口不删除原项目或练习记录。

### V2-T08：S5 阶段式系统设计与 Agent 训练

- **需求与验收编号**：V2-REQ-05，V2-AC-501～507；V2-SEAM-05；依赖 S0、S2，建议 S4 后进行。
- **实施位置（按新增约束调整）**：新增 DesignPractice 服务/Store/控制器、两个合成场景与阶段规则、`design_stage_evaluator` 提示词、配置/工作台/汇总页面；不扩展 V1 InterviewMode。
- **需要保存的数据**：独立 design_session 记录，保存五阶段草稿、提交版本、所依赖的有效前序版本和反馈；通过 operations 处理生成，最多每阶段 20 次提交。
- **先写会失败的测试**：缺必填、越级推进、模型指令切阶段、低反馈但用户合法继续、前序修改后旧反馈仍有效、旧请求迟到、重复提交、重启、未完成强行生成完整评价、合理替代方案被模板否决。
- **实现后怎样检查**：每次只保存一阶段真实产物，模型反馈成功后显式推进；完成汇总确定性组合；同时覆盖提前结束和回到前阶段导致 STALE 的流程。
- **风险与回退**：状态机与版本依赖；不共用 V1 题号；关闭新入口保留产物，原项目深挖按既有两次追问规则继续可用。

## 4. S6：验证完整软件流程

V2-T09 依赖所有功能切片的适用局部检查通过，再执行跨功能验证。先审查实现与获批规格是否一致，修复阻断后进行系统验收。

| 场景 | 要验证的行为 | 关联 |
|---|---|---|
| V1 存量兼容 | 升级前后旧会话/报告/资料/押题内容相同，原三路径、刷新、快捷发送与失败恢复有效 | V2-AC-601、V2-AC-602 |
| F1→F2→F1 | 来源导入、确认、独立重答、对照、用户调度、档案证据连通 | V2-AC-101～107、V2-AC-201～208 |
| F3→原专项→F3 | 精确要求和训练来源，不以开页面作为 DONE；新诊断保留旧清单历史 | V2-AC-301～306 |
| F4→F2 | 确认故事版本对应题目与回答；修改故事不改已提交练习；表达评价不推断音频 | V2-AC-401～406 |
