## 1. 怎样阅读本规范

日期为 2026-10-15。需求状态为已冻结（Requirement Status：FROZEN），审核状态为已批准（Review Status：APPROVED）。已批准范围和决定见 [PROJECT_BRIEF.md](PROJECT_BRIEF.md)，实际验证及缺口见 [VERIFICATION.md](VERIFICATION.md)。

第 2～6 节分别描述五项功能，第 7 节列共同约束，第 8 节列验证入口。REQ 是需求编号，AC 是验收标准，SEAM 是页面、接口或数据库中的验证入口；这些编号用于对照设计和计划，不因调整顺序而重排。

| 术语 | 含义 |
|---|---|
| JD / STAR / Mock | JD 是岗位描述；STAR 是情境、任务、行动、结果的表达结构；Mock 是明确标识的模拟模型 |
| 快照 / 版本 | 快照保存某一时刻的原文；内容变更产生新版本，旧版本继续保留 |
| 幂等 / 版本冲突 | 同一请求重复提交只保存一份有效结果；旧页面试图修改已更新的内容时，拒绝覆盖并提示冲突 |
| 阶段产物 | 用户在某个设计阶段提交的结构化文本，例如需求、接口或架构说明 |
| 原始证据 | 用户提交的回答、资料片段、JD、用户补充事实及其当时快照；不含模型判词 |
| 模型结论 | 报告中的错误、遗漏、未知、比较结果和阶段反馈；需要引用，允许用户提出异议 |
| 用户确认 | 用户接受某候选作为练习目标或声明事实真实；不等于模型判断被客观证明 |
| 复习项 | 一道来源主问题及相关追问形成的待练问题组；可有多个发现与技能标签 |
| 单题案例 | 一条明确的主问题或追问、它的必要前文、资料快照和评分规则组成的不可变练习基准 |
| 独立尝试 | 一次新提交的真实回答；“独立记录”不等于“从未看过解析” |
| 评分协议 | 规则版本、提示词摘要、输出结构版本，以及实际请求使用的模型、参数和服务标识 |

自动提取、模型推断、用户补充、用户确认在页面上分别标识；颜色之外必须有文字。以下所有“应当”均是候选验收要求。

## 2. V2-REQ-01：错题复习与能力档案

### 入口与流程

报告页逐题区域提供“整理为复习项”，仍保留原“专项练习”入口；新增 `/review` 队列与 `/skills` 证据档案。没有报告时说明来源要求并引导开始原有面试。

读取已完成且报告 READY 的一场会话 → 提取每题 `incorrect / missing / uncertain` → 展示原问题、全部相关问答与原报告结论 → 用户确认标签及需练内容 → 入队 → 原题重答或原有专项练习 → 保存本次结果 → 用户选择后续复习动作。

### 业务规则

1. 提取直接保留报告条目及原分类，不新调用模型重写历史结论。旧报告的 `evidence[]` 是整题依据，不能伪装成每条错误的精确引用；缺少精确关系时显示“仅有整题依据”。
2. 一个来源 `(sessionId, questionIndex)` 对应一个复习项；多条错误或多个技能进入同项。重复导入相同报告摘要不新增。来源报告内容改变时追加版本并等待确认，保留旧判断。
3. 不自动合并不同会话或题目的记录。它们可因同一稳定 `skillId` 在档案中聚合，原问题与证据仍独立。技能别名只能映射到已有 ID；不确定时为“未归类”，用户可选目录内标签。修改标签只改变归类，不改原结论。
4. 候选默认 `PENDING_CONFIRMATION`。确认有错误/遗漏的项进入 `DUE`；只有未知的项进入 `WAITING_EVIDENCE`，不计入错题数量。混合项分别呈现，未知条目不参与“已修正错误”计数。
5. 用户可对某条结论提出异议并说明原因。被质疑条目保留原文，排除在自动薄弱统计和诊断依据之外；确认保留仅表示愿意练习。未归类项可入队，但不计入具体技能。
6. 队列按 `nextReviewAt`、创建时间、ID 稳定排序；入队即到期。开始练习进入 `IN_PROGRESS`，离开可继续或返回待复习，网络失败不完成。有效尝试及反馈保存后，用户选择“明日继续”“3 天后再练”或“本轮完成”；分别设为 `DUE +1 天`、`DUE +3 天`、`RESOLVED`。间隔按 24/72 小时计算，显示为本地时间；无后台通知。
7. 手动结束本轮仅表示队列工作完成；即使仍有模型疑点，也保留并显示“用户结束本轮”。同题出现新确认的问题时重新进入 DUE，保留此前完成事件；不同题暴露同技能时形成新复习项。归档项不自动重新激活，显示新发现由用户恢复。
8. 自评只有“未评 / 需要练习 / 基本理解 / 自认为掌握”，与模型观察分栏。档案展示已确认来源、争议、修正观察和时间线，不绘制跨模型总分趋势；单次评分或用户点击完成都不升级为“能力提升”。

### 状态如何变化

| 状态值 | 用户看到的含义 | 允许的后续变化 |
|---|---|---|
| PENDING_CONFIRMATION | 待确认候选 | 确认后进入 DUE 或 WAITING_EVIDENCE，也可归档 ARCHIVED |
| DUE | 已安排复习，按到期时间显示 | 开始练习后进入 IN_PROGRESS |
| IN_PROGRESS | 练习中 | 有效结果保存后，由用户选择继续复习 DUE 或结束本轮 RESOLVED |
| WAITING_EVIDENCE | 只有未知项，待补充证据 | 补充可用证据并确认后，才能进入 DUE |
| RESOLVED | 用户结束本轮 | 有新确认问题后，才重新进入 DUE |
| ARCHIVED | 已归档 | 用户恢复后，回到归档前的状态 |

非生成中的状态可归档。确认、异议、复习时间调整和自评均保存为事件记录。

### 验收标准

| 编号 | 可判定结果 |
|---|---|
| V2-AC-101 | 导入含错误、遗漏、未知的旧报告，三类不混淆；可回到原问答和整题依据，缺失逐条引用时明确标记 |
| V2-AC-102 | 同报告重复导入、断网重放和双标签确认均不重复建项；报告内容变化保留两个来源版本并等待确认 |
| V2-AC-103 | 同题多发现聚合，不同题不自动合并；别名映射到稳定 ID，未知标签不由模型创建；更改标签可追溯 |
| V2-AC-104 | 全部为未知时不计错题、不自动排定复习日；用户异议不删除原结论，并从自动诊断依据中排除 |
| V2-AC-105 | 练习失败不完成；1/3 天调度可重复验证；手动完成与新问题重新入队均保留历史；归档项不偷偷恢复 |
| V2-AC-106 | 自评、模型观察和用户结束本轮独立展示；单次高分或重复提交不触发能力提升结论 |
| V2-AC-107 | 原专项练习保留 `focus / role / level`；新来源关联能回到复习项，返回的报告经确认更新证据，不另建一套出题器 |

## 3. V2-REQ-02：同题二答与进步对照

### 入口与流程

报告逐题原始问答或复习项 → 选择一条已回答的主问题/追问 → 确认案例边界与解析暴露状态 → 新建尝试 → 写新回答并提交 → 评估 → 选两次尝试对照。草稿、已提交答案和评估状态分开；服务端保存提交，浏览器沿用草稿恢复方式。

### 业务规则

1. 一次案例只针对一条 `ASSISTANT` 消息及紧随的 `USER` 回答，不把主问题加追问合并为“第一次答案”。必要的前文随案例冻结，排除目标回答及之后的消息；追问可能已经受先前反馈影响，必须展示该边界。
2. 冻结题目字面量、前文、资料快照、输入范围、规则与提示词版本；后续源资料修改不改变案例。若需要新资料或新题干，建立新案例版本，不在原比较组内更新。
3. 原会话与报告不被重写。历史原答可作为只读基准尝试导入；未知的旧模型、规则和解析暴露填写 UNKNOWN，不拿当前配置回填。报告按整题生成的四维总分不能冒充该条回答的原分数。
4. 新尝试记录模型请求与响应中可获得的元数据、实际参数、题目/上下文/规则摘要、起止时间和解析暴露。评估规则明确检查点、错误、遗漏、证据不足和表达建议；单题不虚构“追问应对”评分。
5. 展示解析采用显式操作并记录“系统已提供解析”；来自已展示解析的报告入口保守标记为已提供。用户可声明“看过/未看/不确定”，但不能清除服务端已有暴露记录；旧记录默认不确定。没有提供新 AI 提示功能，只记录已有解析或模板指引。
6. 比较分三级：题目、上下文及已知评分协议一致为 `SAME_PROTOCOL`；题目与上下文一致但协议未知/不同为 `TEXT_ONLY`；题目或上下文不同为 `DIFFERENT_CONTEXT`。后两类不展示进步分差。辅助或未知暴露状态只能描述回答文本变化，不称为独立掌握提升。
7. `TEXT_ONLY` 可由用户明确点击“按同一规则重评这两段原文”，产生新的配对评估记录；保存当前协议，不改原报告、历史分数或旧元数据。新协议对照只说明这两段原文在该协议下的结果。
8. 对照列出两次原文、已修正问题、仍遗漏、新增问题与建议。修正/新增问题必须有对应原答及新答片段；缺失项以明确检查点和被评估全文范围定位，不能伪造不存在的“缺失原文”。不属于所选问题的旧报告发现标为“本次未覆盖”，不自动清除。
9. 请求重放返回同尝试；同键不同回答拒绝。已提交回答不可编辑，修订需新尝试。模型失败只重试该尝试的未完成评估；有效评估完成后不以“重试”偷偷重新评分。切换模型或规则需新评估分组并显示变化。

最小版逐项检查固定要求，结果为“满足 / 有缺口 / 无法判断”，并展示原文变化，不新增单题总分或分差图；V1 原四维展示保留。评分协议在这里指判定规则与执行条件，并不要求把所有变化折算成数字。

### 作答与比较的状态

- 新作答按 `DRAFT → SUBMITTED → EVALUATING → READY / FAILED` 变化，依次表示草稿、已提交、评估中、结果就绪或失败。提交后正文不可修改；失败重试只从 FAILED 开始。
- 历史原答导入为只读 `IMPORTED`，没有新评估，不进入提交或重试流程。
- 比较按 `PENDING → RUNNING → READY / FAILED` 变化，依次表示待执行、执行中、结果就绪或失败。输入不满足比较条件时，直接返回限制说明，不请求模型生成进步结论。
- 服务重启后，将运行中的操作标记为中断 INTERRUPTED。用户明确重试时，继续处理同一资源。

### 验收标准

| 编号 | 可判定结果 |
|---|---|
| V2-AC-201 | 连续两次作答保存两条尝试；原 Session 消息、原报告与第一次答案逐字不变 |
| V2-AC-202 | 每次新评估有案例、上下文、规则、提示词和模型参数摘要；旧记录缺失值为 UNKNOWN，不能使用当前配置冒充历史 |
| V2-AC-203 | 解析已提供、用户自述和未知状态可区分；刷新或重开尝试不能消除已知暴露；辅助尝试不标为独立能力提升 |
| V2-AC-204 | 改变题目、前文、资料、规则或模型条件分别触发明确比较限制；只有符合协议条件时才提供同规则结果 |
| V2-AC-205 | 已修正/新增问题有双侧原文依据，遗漏关联检查点；不在本次问题范围内的发现不被消除；分差不能替代逐项解释 |
| V2-AC-206 | 双击、网络重放、模型失败和重启只保留一条已提交回答；重试不改正文，不在 READY 上重新评分 |
| V2-AC-207 | 旧原文可显式配对重评，新记录标明重评协议与时间；旧分数保留，未知暴露不被“重评成功”抹去 |
| V2-AC-208 | 选择主问题和追问分别形成明确案例；只引用相应回答与必要前文，不用整场评分替代单题评分 |

## 4. V2-REQ-03：JD 差距诊断与短冲刺清单

### 流程与规则

从现有 JD 资料或配置页输入进入诊断 → 选择本机简历/项目及已确认训练记录 → 查看实际发送范围 → 生成最多 12 条带 JD 原文依据的要求 → 用户确认与修订 → 查看要求、材料、训练三列证据 → 选最多 5 个行动项 → 完成或调整清单 → 按新证据显式更新诊断。

- 要求必须来自当前 JD 快照；未明示的“加分项”只能列为建议，不能混入必需要求。本版不提供额外建议要求列表。超过范围时请用户缩小 JD，不能静默遗漏并宣称完整覆盖。
- 材料列为“已提及 / 材料未提及 / 材料不完整”；训练列为“尚未验证 / 练习暴露不足 / 当前有支持证据 / 证据存在争议”。两列独立存在；一句简历关键词不能把训练列改为“已掌握”。“当前有支持证据”只限定被观察的要求片段，不等于符合岗位全部要求。
- 每个要求保留稳定 `requirementId`、JD 原文、重要性来源及用户修订。模型只能推荐重要性和关联关系；用户确认后生效。训练依据只引用接受的观察，排除纯自评和争议结论。
- 清单使用 7 天参考窗口，不做强制倒计时或日历。行动类型限补充材料、验证一个要求、重练一个问题；每项包含目的、要求 ID、优先级依据、具体入口和完成条件。默认优先“JD 明示必需且练习有不足”，其次“明示必需但未验证”，再次其他；同优先级用户可调整。
- 状态为 `TODO / IN_PROGRESS / DONE / SKIPPED`。仅打开练习不完成；训练项至少关联已完成会话/尝试和被确认的对应证据。补充材料由用户确认修订版本。跳过须留原因，手动完成注明用户确认，不推导岗位能力或录用概率。
- 新 JD、材料或训练记录不会自动覆盖诊断。界面显示来源版本变化，用户发起新版诊断；清单更新展示新增、保留、失效与已完成项，确认后才应用。旧诊断、已完成项及证据保留；新旧要求不按近似文本偷偷合并。

| 编号 | 可判定结果 |
|---|---|
| V2-AC-301 | 空 JD 不能生成；每个要求可定位 JD 原文；超出 12 条或输入范围时明确要求缩小，不声称完整诊断 |
| V2-AC-302 | 材料未提及、尚未验证、练习不足分别显示；关键词、自评和单个局部证据不能推出整体掌握或录用概率 |
| V2-AC-303 | 要求与优先级经用户确认才创建清单；每个行动项关联要求、依据和具体操作，活动项不超过 5 个 |
| V2-AC-304 | 原 JD 输入与 `focus` 练习继续可用；新训练来源可追溯；未完成或失败的练习不自动把清单标为 DONE |
| V2-AC-305 | JD/材料/证据变化提示过期；用户确认差异前保留原清单，完成记录不被新版抹去 |

## 5. V2-REQ-04：自我介绍与 STAR 故事库

### 流程与规则

资料库项目入口或 `/stories` → 选择真实项目资料/手填经历 → 选择自我介绍或 STAR → 生成待确认草稿或手工填写 → 逐字段检查来源与待补事实 → 保存并确认版本 → 选择该故事适用的问题 → 进入 F2 单题文本练习 → 查看结构、个人行动、事实一致性和表达建议。

- 自我介绍字段为目标岗位、背景、相关经历、个人贡献与下一步诉求；STAR 字段为情境、任务、个人行动、结果、复盘。两者都区分个人行动与团队成果，不新建简历优化或自动投递功能。
- 每个事实字段标记 `MATERIAL_QUOTE / USER_ASSERTION / MODEL_DRAFT / MISSING`，包含来源或用户补充。MODEL_DRAFT 只能是待审表达建议，不成为已确认事实；未知数字和职责留空并显示待补充。
- 模型输出引用必须命中发送的来源片段；数字、单位、主体与事实字段分开校验。结构校验不能证明职责归属正确，仍须用户逐字段确认。对未确认或争议事实禁止生成“已确认故事”。
- 内容修改产生新版本，变更字段及依赖表述的确认失效。旧版本及当时确认保留；源项目后来变化时提醒来源版本已变，不能自动更新历史故事。未改字段可沿用此前确认，需显示其来源版本。
- 只有必需字段确认、缺项明确标为不适用并给出原因的版本可用于练习。“不适用”不能代替个人行动；无法说明个人行动时继续草稿。用户确认表示本人声明，不表示系统外部核验。
- 练习复用 F2 作答与评估，冻结故事版本、问题、评分规则；针对不同问题可复用同一故事但各自独立回答。故事已展示属于辅助准备，反馈只评价文本表达，不推断语速、语气、临场口头表现。归档不删除已用于练习的快照。

故事版本从草稿 DRAFT 变为已确认 CONFIRMED。编辑确认版时，新建 DRAFT，不修改旧版。故事可归档为 ARCHIVED。确认请求必须对应当前版本，旧页面不能确认已经变更的正文。

## 6. V2-REQ-05：阶段式系统设计与 Agent 架构训练

### 入口与流程

在现有开始面试区域添加“分阶段设计训练”入口，进入 `/design-practice`；V1 项目深挖继续使用原入口。首版内置两个明确为合成的案例：订单服务设计、知识库 Agent 设计。用户可补充约束，不提供案例编辑器或自动题库生成。

选择案例及约束 → 需求澄清 → 约束与容量 → 核心实体/API → 架构 → 故障与权衡 → 汇总全部当前阶段产物与反馈。

| 阶段标识 | 必需结构化文本 | 推进约束 |
|---|---|---|
| CLARIFY | 目标、主要用例、范围外事项、待澄清点 | 必填字段有内容；没有待澄清点需明确填写“无” |
| CONSTRAINTS | 功能/非功能约束、容量或成本假设、假设依据 | 未知数字可写未知及验证办法，不能强迫编造 |
| ENTITIES_API | 核心实体、操作/API、输入输出与错误 | 不适用项说明理由；不能整阶段跳过 |
| ARCHITECTURE | 组件职责、关键数据流、存储或状态边界 | 结构化文本即可，不要求图形布局或组件连线数据 |
| TRADEOFFS | 故障场景、恢复、备选方案、取舍与局限 | 至少一个故障和一个备选方案；Agent 案例还覆盖工具权限或失败 |

- 服务端维护阶段与版本；模型只返回本阶段反馈，不能直接跳阶段或宣告完成。用户提交产物后保存不可变版本，再请求反馈；反馈 READY 后由用户点击下一阶段。
- 反馈质量低或仍有缺口时，用户可以带未解决项继续，需明确确认；无效结构、反馈失败不能当作已完成反馈。必要字段缺失时先补输入，不能用模型分数代替输入校验。
- 进行中可回到前一阶段修改：建立新产物版本，所有依赖该版本的后续反馈标记 STALE，保留原产物；再次使用旧产物需显式作为新版本提交并重新评估。已完成训练只读，再练创建新训练。
- 每阶段草稿和提交版本分开；刷新、失败、进程重启可恢复到准确阶段。中断后不重复创建产物；迟到模型响应不能覆盖用户已修改的版本。
- 最终汇总直接组合当前有效产物、反馈及未解决项，不追加一次自由总结模型调用；若用户提前结束，状态为 ENDED_EARLY，明确列出未完成阶段，不展示完整完成评价。
- V1 项目深挖讨论已有项目事实和回答；本功能训练合成场景的方案产出。复用 LLM 调用、引用校验、持久化与 UI 控件，不复用 V1 `questionIndex` 作为阶段状态，不改变每主问题两次追问规则。
- 容量数字、Agent 行为及工具能力只能是案例给定条件、用户假设或来源事实，必须标识。合理替代架构按约束与解释评估，不能仅因不匹配参考方案判错。

## 9. 已批准评审补充行为

以下补充属于既有 V2-REQ-01～06、42 项 AC，不扩张五项范围，优先于早期草案中省略的描述。
