# V6 岗位搜索聚合：竞品调研与 MVP 建议

- 调研日期：2026-10-22（北京时间）。
- 阶段：Thinking 已完成，需求已冻结；三站真实接入待验证，未进入开发。
- 项目基线：`8e53625bfebb58a7833f081c7d856b4c2d618b18`。V6 是本次需求的文档归档目录，正式 Release 仍为 V1。
- 文档职责：保存外部调研、仓库现状、候选功能和验证限制。冻结行为以 [SPEC.md](SPEC.md) 为准；本文不是接口契约或接入成功证明。

## 1. 当前结论与需求入口

**2026-10-22 用户已确认首版完成“输入目标岗位 → 跨平台搜索 → 筛选和收藏 → 保存岗位描述”的闭环。** BOSS、猎聘、智联为三个首版目标，前程无忧暂缓；本轮不做岗位诊断或模型调用。完整行为和验收见 [SPEC.md](SPEC.md)。

初始调研曾建议先做两个可用平台并衔接岗位诊断，用户未采纳该范围。当前要求是**完整功能开发前先验证三站真实搜索、翻页和详情**；运行时允许单站部分失败，但长期不可用的平台不算已支持。

初始调研比较过以下两条路线，供理解访问成本；它们不是当前产品范围的两个待选项：

| 路线 | 适合的优先目标 | 首批候选与限制 |
|---|---|---|
| A：免登录，检索公开职位信息 | 尽快验证聚合、筛选和接入面试训练的价值 | 猎聘、智联已有可读样本；BOSS 的本轮索引结果不相关，前程无忧内容不可用。不能承诺覆盖四站、实时更新或完整 JD |
| B：用户本机登录，工具只读搜索 | 优先保留 BOSS 等原站搜索体验 | 优先验证 BOSS、猎聘；接受人工登录和验证码中断。尚未进行登录态实测，平台授权边界、稳定性及实现方式仍需核验 |

用户在初始调研时暂不决定登录方式，后经 grilling 明确为**后端直接搜索，开发者配置和维护 API 凭据、Cookie 或浏览器会话，用户不登录、不处理验证码**。可组合开源工具并补充适配，首版不依赖付费数据 API。具体工具未选定，本轮未使用招聘账号或读取用户凭据。

## 2. 同类产品有哪些做法值得参考

本轮覆盖五款产品和一个社区聚合项目，选择依据是功能相似度，不是市场份额。官网和使用手册只能证明厂商公开介绍了这些能力；未注册付费账号，也未验证其岗位覆盖率、匹配准确率或求职效果。

| 产品 | 本轮取得的证据 | 可借鉴的功能 | 对本项目的取舍 |
|---|---|---|---|
| **AI 工作快搜** | 官网介绍跨平台／多城市搜索、排除词、JD 摘要、匹配、去重、进度管理；商店说明列出 BOSS、51Job、智联，并提示登录与人工验证 [S01、S02] | 一次设置搜索条件，集中处理重复与不合适岗位；展示跨平台来源 | 与需求最接近。借鉴搜索、排除和去重；自动沟通、投递、邮件和 PDF 不进入首版建议。猎聘支持情况未得到本轮说明佐证 |
| **求职方舟 AI** | 官方手册描述简历／偏好驱动搜索、聚合表格、条件筛选、来源详情及跳转投递；其自述来源含四家目标平台、企业官网和高校渠道 [S03] | 偏好可编辑、结果可筛选、点击回原站；找岗位与后续准备衔接 | 借鉴流程；不照搬强制上传简历、公司信用分及庞大来源覆盖。覆盖数量和“精准”属于厂商宣称，未独立验证 |
| **Jobright** | 官网介绍个性化职位匹配、提醒、简历调整、申请填写与内推关系 [S04] | 从目标条件得到候选岗位，减少逐站浏览；辅助理解匹配依据 | 用于参考匹配体验；本轮没有证据证明支持国内四站，不作为国内数据供应方 |
| **Teal Job Tracker** | 官方页面介绍浏览器收藏、集中跟踪、JD 关键词提示、跟进和联系人管理 [S05] | 收藏原始职位、清晰的个人处理状态、职位和准备材料关联 | 首版借鉴收藏与信息保存；完整求职看板、联系人、邮件跟进暂缓。职位收藏与自动搜索是不同能力 |
| **Huntr** | 官网介绍职位剪藏、保存 JD／薪资／地点、申请进度、备注和简历匹配 [S06] | 原网页变化后仍可回看保存内容；减少重复处理 | 优先保留 JD 快照与来源；不用简历分数代替“是否值得投”的解释 |
| **awesome-jobs 社区聚合项目** | V2EX 作者介绍大厂开发岗聚合、公司／地点筛选和推送；回复提到原链接落到招聘首页、地域覆盖不足 [C01] | 集中浏览和按城市筛选有实际使用场景 | 验收必须检查具体职位跳转、地域正确性。帖子是历史样本，未证明该站当前覆盖或持续运营状况 |

### 2.1 从调研得到的产品判断

以下是结合证据形成的建议，不是已经做过用户实验的结论：

1. **聚合后的信息质量比数量更重要。** 原链接失效、地点不符、同岗重复，会把筛选成本重新交还给用户。[C01、S01]
2. **搜索和个人收藏应分开。** 搜索结果可能变化，用户保存的 JD 和准备记录需要稳定保留；刷新不应清空收藏或覆盖已有训练输入。Teal、Huntr 的组织方式值得参考。[S05、S06]
3. **本项目的优势是与训练衔接。** 已有资料库、岗位诊断和综合面试，不必再建一套简历编辑器或求职管理系统。[R02–R06]
4. **匹配需要解释和未知状态。** 首版先显示命中的关键词、明确不符条件和缺失字段。AI 给出一个高分，不能证明实际符合学历、经验或薪资要求。

### 2.2 社区材料能说明什么

- V2EX 的 2023 年求推荐帖直接提到多招聘 App 来回切换的麻烦，但没有回复，属于单个需求线索，不能当作需求规模证明。[C02]
- 2025 年聚合项目帖有正面评价，也有“与直接去招聘网站搜索有何区别”的质疑，以及跳转目标错误的具体反馈。本轮通过公开 API 读到了正文与 9 条回复。[C01]
- B 站进行了“招聘 聚合”和“BOSS直聘找工作”两次搜索。前者相关性差，后者包含求职技巧、推广和个体抱怨；只读取标题及简介，未观看视频或读取评论，因此不据此声称用户普遍需要自动投递。[C03]
- 小红书、Reddit、Twitter 没有可用后端，本轮未取得这些平台的直接讨论证据。

## 3. 四个平台的接入可行性

### 3.1 本轮实际观察

以下是通过 Exa 索引及 Jina Reader 取得的公开文本。**Jina 是第三方读取服务，不是本机浏览器登录测试，也不是招聘平台官方 API。** 页面可读不证明稳定分页、完整字段、实时职位或生产使用授权。

| 平台 | 实际取得的内容 | 发现的限制 | 本轮结论 |
|---|---|---|---|
| BOSS 直聘 | 官网首页、职位入口与公开搜索链接；定向 Exa 检索返回 1 条岗位详情，但实际是南京保洁，与探针不符 [S07、E01] | 公开索引无法满足本轮技术岗搜索目标；未进行登录态搜索和详情校验 | 两条路线都不能据此宣称已接入；若 BOSS 必须首发，优先验证路线 B |
| 猎聘 | Java 关键词列表返回非空职位信息；一个深圳 Java 详情可读；综合检索请求 8 条、实际 8 条都来自猎聘 [S08、E01、E02] | 列表与详情不是同一条已验证的自动跳转链；城市筛选、分页、稳定性未验收；索引与详情字段不一致 | 路线 A 的首批候选；路线 B 也可评估，尚未成为稳定适配器 |
| 智联招聘 | Java 分类页可读；定向搜索取得 3 条技术岗；读取其中一个详情取得 JD 与基本信息 [S09、E01、E03] | 详情提示登录查看完整内容，薪资缺失、地址隐藏；分类页不等于带城市条件的站内搜索 | 可作为路线 A 的候选，但必须保留字段缺失、摘要和完整正文的区别 |
| 前程无忧 | 索引返回 2 个岗位地址与 1 个分类页；读取职位站首页出现滑块验证 [S10、E01] | 索引摘要是不可用的编码文本；没有获得可用于聚合的完整职位数据 | 本轮没有通过公开读取；路线 B 也未经实测，不能因存在适配代码就标为支持 |

四站的公开接口检索没有找到足以确认“个人开发者可直接调用、覆盖四站、长期可用”的官方职位搜索 API。这里的结论是**本轮未找到**，不等于断言不存在合作接口。招聘方的职位发布、简历同步接口也不能直接当作求职者的全站搜索接口。

### 3.2 三个会影响设计的真实样本

**样本一：索引与详情字段不一致。** 猎聘职位 `1985481475` 的 Exa 摘要显示 `9–14k`、`9月8日更新`；随后经 Jina 读取同一 URL 显示 `7–12k`、`9月26日更新`。这是两次读取的观察差异，可能来自缓存、索引时间或源站变化，未定位原因，也没有确认哪个视图等于招聘方此刻数据。[E02]

设计含义：保留字段来源、读取时间和原始文本；搜索摘要不能冒充最新详情。“本次发现时间”“源站显示的发布时间／更新时间”“最近核验时间”必须分开，缺少年份不能擅自补成今年。

**样本二：看得到 JD，不等于字段齐全。** 智联职位 `CCL1505864390J40948769008` 的搜索摘要有 `2.3–3.5万·13薪`，随后读取详情薪资为缺失，地址部分隐藏，并提示登录查看完整内容。[E03]

设计含义：未知薪资不是零薪资；不能从页面底部“相似职位”提取薪资填回当前职位；搜索摘要的旧值如展示，须注明来源与未核验状态。仅凭页面资源名也不判断职位已下架。

**样本三：搜索引擎容易偏向单一来源。** 一次包含四站范围的检索，8 个结果全部来自猎聘；拆为平台查询后，BOSS 出现不相关岗位，前程无忧结果缺乏可读内容。[E01]

设计含义：每个平台分别查询、校验条件和展示状态。即便收到非空响应，也必须核对岗位、地区及内容质量；不能把一次全网检索包装成“四站搜索完成”。

### 3.3 使用与数据边界

BOSS 的公开 `robots.txt` 对带查询参数等路径列出抓取限制；本轮用户协议页面未取得正文，因此不引用其他产品的协议代替 BOSS 直聘条款，也不据此作出法律结论。[S11]

后续接入前，需要针对选定平台和方式核对条款及授权。登录只解决访问条件，不能自动证明批量采集获准。候选实现应在验证码、登录失效或限流时暂停并清楚提示，不绕过验证；本轮不进行批量爬取、自动沟通或简历投递。

## 4. 两条路线怎么选，现成工具能否复用

### 4.1 初始路线比较

下表保留调研时的免登录与用户本机登录比较。当前采用开发者维护访问配置、后端搜索的边界；不要求普通用户完成表中的登录与人工接管操作。

| 比较项 | A：免登录公开搜索 | B：本机登录后只读搜索 |
|---|---|---|
| 数据路径 | 按平台检索公开索引，必要时读取允许访问的公开详情 | 用户控制的本机浏览器会话读取原站允许访问的搜索结果和详情 |
| 使用门槛 | 不需要招聘账号；搜索服务可能需要 Key 或额度 | 需要人工登录；可能需要专用浏览器配置或扩展，具体实现未选 |
| BOSS 优先目标 | 本轮证据不足，不宜承诺 | 更贴近目标，但仍需真正跑通搜索与详情 |
| 覆盖与时效 | 依赖搜索引擎收录，可能漏岗、过时、偏向某站 | 能观察原站当前会话可见结果；仍非全量，也无法保证岗位真实在招 |
| 筛选质量 | 部分条件只能在已返回结果中筛；未知字段较多 | 可利用原站筛选，但各站条件、编码和范围不同 |
| 失败模式 | 索引无结果、内容过时、页面不可读、额度限制 | 登录过期、验证码、限流、页面改版、浏览器关闭 |
| 隐私边界 | 查询词发给搜索服务；公开 URL 发给读取服务；不应携带个人简历或登录态 | 登录态留在本机受控范围；不把 Cookie、带凭据链接、完整账户页面发给外部读取或模型服务 |
| 工程与维护 | 起步相对轻；仍需来源校验、去重和异常处理 | 初始及持续维护相对高；需要运行环境、人工接管、会话恢复和逐站验证 |
| 适用判断 | 接受有限覆盖，优先验证筛选与训练衔接 | BOSS 是关键来源，并愿意承担登录与人工验证成本 |

上述比较不证明工具已可用。当前无论采用哪种具体读取手段，都必须满足三站接入门槛和开发者维护配置的边界；不能把纯手工导入算作自动聚合，或把单平台结果算作三站完成。

官方／授权数据 API 仍是值得优先核查的接入方式，但暂未取得满足目标的可用接口与报价。聚合数据的招聘 API 搜索摘要标为“维护中”，Jina 实际读取被阻断；没有试调用，不能作为现成可用依赖。[S12]

手工粘贴 JD、保存职位链接可作为两条路线的补充；它可以保证用户有办法保存看中的岗位，**不能替代自动搜索聚合的核心验收**。

### 4.2 依赖与公开源码候选

本轮只查资料和少量源码，没有安装、运行或将候选实现引入项目。软件许可只涉及代码复用，不自动赋予招聘平台数据访问权。

| 候选 | 核验结果 | 是否建议直接作为首版依赖 |
|---|---|---|
| agent-reach | 本机 Exa、Jina、GitHub、V2EX、B 站搜索实际返回内容；现有 career 文档主要提供 LinkedIn 路由，没有四家国内平台的现成接入说明 [T01] | 用于本轮调研。不能把 Agent 的调研工具直接等同于用户应用已经拥有的运行能力 |
| `loks666/get_jobs` | README 明确当前维护 BOSS、猎聘，智联等停止维护；依赖浏览器与扫码／Cookie，README 说明不支持服务器部署。当前 LICENSE 为 PolyForm Noncommercial 1.0.0 [S13] | 不是已验证的只读搜索 API。包含自动投递／沟通，必须先证明能单独调用搜索并隔离写入；本机后端集成仍需验证，非商业限制需核对 |
| `speedyapply/JobSpy` | README 列出 LinkedIn、Indeed 等来源，未列国内四站；MIT。国家参数包含 China 也不等于支持 BOSS 等平台 [S14] | 与首版国内范围不匹配，暂不引入 |
| `mergedao/mcp-jobs` | 固定提交 `23e223d` 使用 Playwright／Cheerio；实际采集规则只有 BOSS、猎聘及两者详情，智联虽在 URL 清单中却无匹配规则。城市拼入关键词，猎聘城市参数固定 `000`；未见平台登录态管理。`package.json` 声明 ISC，根目录未见独立 LICENSE [S15] | 不能作为三站现成依赖，城市参数也不证明地域筛选有效；可参考结构，需核验许可、登录态与实际返回 |
| `bosskit` | 固定 main 提交 `bf1e109` 与 docs.rs `0.8.1` 均仅支持 BOSS；提供搜索、详情、CLI JSON 和 stdio MCP，要求有效 BOSS Cookie，运行无需浏览器；MIT [S16] | 仅列为 BOSS 单站验证候选，不能承担猎聘、智联；登录失效或风控仍会失败 |

**事实更正：** 初稿以动态 `latest` 页面及索引中的适配器链接推断 BossKit 有智联／51Job 源码，这一依据不足。固定 0.8.1 的 provider 目录只有 `mod.rs`、`zhipin.rs` 和 `fixtures`，不能继续据旧记录承诺多站支持。mcp-jobs 的“URL 清单包含智联”和“有城市参数”也不等于实际完成对应能力。以上均为静态核查，未运行三站搜索。

建议按“现有工程能力 → 满足目标且可验证的依赖 → 少量业务适配”的顺序选择。若只有搜索、字段转换和异常分类需要自建，就在现有单一工程中实现；不要另起 V6 后端、App 或版本化服务。

| P0 | 保存 JD 并进入岗位诊断 | 用户预览确认后保存为资料库 JD；进入现有诊断页选择该资料；模型调用继续沿用输入预览和用户触发 | 把找到的岗位转为可执行的面试准备 |

“外包”“双休”“远程”“学历不限”等标签只有原文明确说明时才可据其筛选。没有说明应显示未知；公司名称含“科技”不能成为自研公司证据，招聘平台审核标志也不能转换为本产品的企业信誉分。

### 5.1 筛选与去重需要明确的规则

- **薪资**：保留 `15–25k·13薪` 等原文，同时分开记录币种、周期、范围和薪数。月薪、年薪、日薪不能直接混排；面议或缺失显示未知，不自行按 12 薪补算。筛选时明确“区间重叠”还是“下限达到”，具体口径待确认。
- **经验与学历**：缺失不视为不限；原站的区间要求不能伪装成精确匹配。用户选择硬筛选时，说明未知字段如何处理。
- **跨平台去重**：公司、岗位和城市相同只形成疑似关联；校招／社招、不同部门、不同地点和猎头代招可能是不同职位。首版保留独立来源，不做不可恢复的自动合并。
- **时间与有效性**：发布时间、读取时间、核验时间分开；访问失败或验证码不等于岗位下架。刷新后消失也不能立即判定已关闭。
- **投递状态**：点击原链接只表示打开了平台；不能自动标记已投递。首版若只做收藏与忽略，无需引入完整投递状态机。

### 5.2 最小用户流程和页面状态

1. 用户输入岗位与城市，确认本次来源；界面说明哪些条件由原站处理、哪些只在返回结果中筛选。
2. 用户发起搜索，逐步看到各来源的结果或失败原因；慢平台不遮住已经返回的岗位。
3. 用户筛选、收藏或忽略；打开原岗位核对，返回后保留条件和列表位置。
4. 对看中的岗位预览 JD；缺少正文时允许用户补充，注明手工输入来源；不能把几句搜索摘要当作完整 JD。
5. 用户确认保存到资料库，然后进入既有岗位诊断流程；搜索和收藏本身不自动发送简历、不触发批量模型调用。

建议沿用现有操作型工作台：顶部条件区和来源状态，中间可扫描结果列表，详情在明确入口打开。现在不定稿视觉布局；选择范围后再更新既有 `DESIGN.md`。

| 状态 | 用户应看到什么 | 可继续的操作 |
|---|---|---|
| 未搜索／空收藏 | 简明输入引导，不填充虚构岗位 | 设置条件或发起搜索 |
| 搜索中 | 来源级进度和已返回结果 | 查看已有结果、停止本次搜索 |
| 真正无结果 | 明确哪些来源成功查询且返回空 | 修改条件再次搜索 |
| 部分失败 | 保留成功结果，指出失败来源与原因 | 重试失败来源、人工处理验证、查看原站 |
| 全部失败 | 明确失败，不显示“没有岗位” | 修复配置或登录，保留输入再试 |
| 详情不完整／过时 | 字段未知、正文不完整和读取时间可见 | 原站核对、补充 JD、保留收藏 |

## 7. 接入验证应先于完整开发

### 7.1 小规模接入验证建议

以下验证**尚未执行**。用户已确定后端访问责任和三站范围，下一阶段应依据 [SPEC 第 7 节](SPEC.md#7-限制非功能要求与验收边界)落实；本节数量仍是有界验证建议，不是已执行证据：

1. 对 BOSS、猎聘、智联使用“Java 后端＋深圳”样例；可增加一组对照条件，验证条件确实改变结果，避免固定推荐页冒充搜索。
2. 每平台最多读取两页、抽查五个职位；不同时间各执行一次。记录结果数、条件匹配、字段完整性、具体原链接及是否需要登录或验证。数量只是建议的有界验证预算，不是覆盖率承诺。
3. 核对列表到详情的真实链路、职位身份和正文；特别检查相关推荐是否误混入当前职位字段。
4. 若出现登录失效、验证码或限流，验证工具能停止并说明原因，不自动转用隐蔽替代路径。
5. 记录外部调用量、耗时、费用来源、人工操作次数和失败情况；没有计费信息时标未知，不编造“免费稳定”。

**进入完整功能开发的门槛**：三站分别通过真实搜索、翻页和详情链路核验，返回与条件相关、带具体原链接的岗位；缺失可辨认，失败不显示为空结果。做不到时先报告具体缺口并讨论，不静默降为两站，也不用 Mock 或手工粘贴替代自动聚合。

### 7.2 后续 MVP 验收候选

| 需要证明的结果 | 验证方式 |
|---|---|
| 真正按目标跨平台搜索 | 同一组条件对三个目标来源执行，核验翻页与详情，抽查岗位和城市；结果注明来源和时间 |

| 不混淆身份／误去重 | 同平台重复、跨平台相同 ID、同公司异地同名职位；保存与撤销保持各自来源 |
| 不编造缺失字段 | 薪资缺失、面议、不同薪资周期、未知发布时间、正文不完整；不以默认值冒充已知事实 |
| 收藏真正留存 | 刷新和重启后仍可查，重复操作不产生多份相同收藏；取消收藏不删除 JD |

| 真实质量与软件测试分开 | 解析／路由／恢复测试用明确合成样本；另记录真实平台样本。若增加 AI 功能，再单独验证质量与费用 |

价值判断建议先用真实使用记录：相同目标下，是否减少跨站重复输入、是否找到值得进一步核对的岗位、是否能直接开始准备。尚无用户使用基线，不预设节省时间比例、匹配准确率或录用率。

## 11. 岗位搜索的现状分析与视觉参考（2026-10-22，方向待确认）

### 11.1 范围、依据与证据边界

本节承接已确认的 UX 选择：面向国内技术岗求职者，以电脑上集中选岗为主，先扫描与收藏，再精读少量 JD。信息入口为「岗位搜索」，模块内为「搜索职位／我的收藏」；桌面列表与详情并排，手机进入详情后可返回列表并恢复位置。已保存 JD 仍由「个人资料库 → 目标 JD」管理。

岗位搜索页尚未实现，本轮使用运行中的演示空间作为现状基线：资料库 `/materials`、专项训练 `/review`、面试历史 `/history`。演示数据为虚构样例；未操作日常求职资料、未调用模型、未登录招聘账号。工作区同期存在另一项「投递管理 MVP」改动，本节只讨论原岗位搜索需求，不改变其范围或实施顺序，也不把投递管理视为搜索聚合已经实现。

本节是现状观察与候选方向，不是已批准的页面设计，不修改 SPEC、全局 DESIGN 或工程实现。浏览器证据来自本次实际打开的页面；组件兼容性来自本仓库源码阅读。未进行正式可访问性审计、性能测试、故障注入或三站接入验收。

**需要优化的重点**：岗位结果的扫描密度；来源选择、结果来源筛选与平台运行状态的区分；跨站折叠后的来源可追溯性；长 JD 的阅读宽度与稳定操作区；移动端搜索条件对首屏的占用。上述均为新页面设计问题，不是要求重做现有资料库或训练流程。

**必须保留的业务边界**：单组关键词＋单城市；BOSS／猎聘／智联三源目标及部分失败；四项筛选只作用于已获取结果；明确同岗才折叠；按同一个来源匹配全部筛选条件；收藏与保存 JD 独立；用户不负责招聘平台登录或验证码；不加入诊断、AI 匹配、自动投递及新 JD 管理系统。

### 11.4 两个候选方向

两个方向均保留已确认的「搜索职位／我的收藏」及桌面双栏，不引入新的业务操作。以下比例与表现只是方向说明，具体尺寸、断点和组件状态待用户确认方向后制定。

| 比较项 | A：紧凑双栏选岗工作台（推荐） | B：宽松双栏职位阅读台 |
|---|---|---|
| 结构 | 左侧紧凑行列表，右侧持续详情；两栏约四比六，按实际宽度调整 | 左侧留白较多的轻卡片，右侧更强调长文阅读与标题留白 |
| 视觉质量 | 精确、克制，层级来自对齐、字重、细分隔线和选中反馈 | 更舒展，条目边界更明显，适合少量机会的仔细阅读 |
| 核心操作 | 同屏扫描较多职位，收藏易触达，切换比较成本低 | 单条易读，但同屏结果较少，需要更多滚动 |
| 产品一致性 | 高，直接延续训练工作台与历史平面列表 | 中高，接近资料卡片的舒展感，但需要建立岗位轻卡片的局部规则 |
| 实现成本 | 较低的新增视觉工作；仍需处理多源状态、筛选、去重和保存流程 | 比 A 多一层间距／卡片／响应式细节，但无须更换技术栈 |
| 主要风险 | 不能靠缩小关键信息字号换密度；需避免来源标签与筛选挤在一起 | 卡片间距和摘要占高容易削弱“先扫描收藏”的效率 |

推荐 A：它最符合用户明确的扫描→收藏→精读节奏，与当前产品已有双栏和行列表更一致。吸收 Indeed 的主从组织、猎聘的字段顺序、Teal 的来源与保存时间表达；不拼接三套品牌视觉。实现成本只比较前端设计增量，不包括三站数据接入。

### 11.5 无论选择哪个方向，都应落实的状态表达

| 场景 | 建议表现及恢复入口 |
|---|---|
| 尚未搜索／空收藏 | 简短说明与对应入口，不填虚构岗位，不用大面积宣传插画占据工作区 |
| 搜索中／部分返回 | 平台状态持续可见，已有列表可操作；停止入口明确，不用全屏遮罩挡住已返回结果 |
| 某平台失败／全部失败 | 成功结果继续可用；失败来源、可理解原因及单站重试就近展示。配置失效由开发者处理，不要求用户登录或解验证码 |
| 真正没有结果／筛选后为零 | 区分“已成功查询但未找到”与“当前筛选无匹配”；后者保留已获取总数及清除筛选入口 |
| 详情缺失／字段未知 | 在字段或正文位置提示缺失，保留原站跳转、重试与已有内容收藏；保存 JD 前可补正文 |
