## 3. 失败、修复与复验

1. **功能尚未实现时的失败测试。** M1 最初 4 项 HTTP 测试失败，随后实现通过；M2 页面／导航与 M3 CSV 先记录失败再实现。原始记录为 `m1-red.log`、`m2-red.log`、`m3-red.log` 等，最终结果统一以标准检查为准。
2. **专项审查发现两处边界。** CSV 对 Unicode 空白及全角公式符号的保护不足，前端年份小于 1000 时不足四位；补失败测试后分别修复公式前缀识别与年份补零，最终标准检查通过。
3. **浏览器脚本的日期输入格式。** 首批 24 项中，投递完整流程在 `datetime-local` 填入带零秒的字符串时被 Playwright 拒绝（Malformed value），尚未请求后端；改用有效的分钟格式，最终 8 项投递验收通过。其余 16 项旧业务回归当批通过。
4. **768px 录入尺寸。** 补充检查发现表单仍为 14px；将 768px 以下录入字号改为 16px、表单操作按钮至少 44px。对应失败记录 `e2e-refine-red.log`，最终全部视口通过。
5. **日常旧数据库首次启动被预检查拒绝。** 新增表尚不存在时，严格预检查报 `V2_SCHEMA_UNSUPPORTED`，发生在数据库写入前。立即恢复原 JAR 与服务；补充旧库失败测试，只允许已批准附加表及索引缺失，已有或未知结构仍严格验证。重新标准检查、隔离启动／重启和日常更新后通过，原数据摘要一致。
6. **只读核验脚本定位错误。** 首次按「资料库」精确寻找演示页标题超时；核对现有源码实际标题为「我的资料库」后修正脚本，日常／演示核验通过，未修改产品页面。

中途一次标准检查因会话中断未完成，未将残缺日志作为成功证据；最后重新执行的 `final-standard-tests.log` 有完整成功结尾和退出码 0。
