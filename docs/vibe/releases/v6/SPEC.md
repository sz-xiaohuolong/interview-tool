## 本阶段：投递管理 MVP（FROZEN）

面向本机求职用户，提供像表格一样直接的投递记录管理。入口为独立「求职管理」页面；用户新增岗位、补充计划、手动更新状态，并通过 CSV 备份或迁移。正式 Release 仍为 V1，V6 仅记录本轮文档。

### 冻结功能与规则

| 编号 | 能力与规则 |
|---|---|
| JA-REQ-01 | 岗位新增、全字段编辑、归档／恢复、二次确认删除；同公司多岗位独立保留，归档与状态独立 |
| JA-REQ-02 | 公司和岗位必填；地点、平台、原始链接、JD 选填；岗位类型为校招、日常实习、暑期实习、正式岗位、其他。仅人工录入，不抓取链接 |
| JA-REQ-03 | 七种状态 TO_APPLY／APPLIED／ASSESSMENT／INTERVIEW／OFFER／REJECTED／WITHDRAWN；默认待投递，任意手动纠正，打开链接不改状态 |
| JA-REQ-04 | 投递日期、下次行动日期、面试日期时间及说明、备注均可空；日期不做 UTC 换日，面试时刻携带时区偏移并按浏览器本地时间展示 |
| JA-REQ-05 | 表格包含公司、岗位、地点、平台、状态、投递／行动日期与操作；公司搜索、状态筛选、日期排序、归档筛选、详情抽屉；覆盖空、加载、失败、手机布局 |
| JA-REQ-06 | 同一 SQLite 内独立表；重启保留；UTF-8 CSV 完整导出、模板、预览后确认导入；逐行错误、重复提示、公式防护、非破坏性初始化 |

新增首屏只要求公司和岗位，状态默认待投递；其他字段按需展开。编辑保留全部原内容，保存失败保持表单。表格内可直接修改状态。详情展示完整 JD、备注及面试安排。删除确认明确公司和岗位，取消不写入；归档不删除或修改状态。失败可重试且不冒充空数据。归档列表可恢复。

输入限制由技术设计落实：不静默裁剪、纠正或丢弃字段；链接仅允许 HTTP(S)。CSV 预览显示总数、新增数、重复数和错误数；出现无效行时整批不写入，用户修正文件后重试；重复数据明确跳过，同 ID 不同内容明确冲突，绝不覆盖。身份与可逆公式转义见 [技术设计](TECH_DESIGN.md)。

## 1. 产品概述与背景

用户需要针对同一求职目标查看多个招聘平台。反复输入条件、比较重复岗位以及整理岗位描述，增加了选岗成本。本功能把这些操作集中在现有本机应用中，让搜索结果能够转为稳定保留的收藏和 JD 资料。

竞品调研提供了多源搜索、来源保留、职位收藏和 JD 快照的参考，详见 [RESEARCH 第 2 节](RESEARCH.md#2-同类产品有哪些做法值得参考)。调研中的“先两站”“进入岗位诊断”等初始建议已被本次确认范围替代。

成功意味着三个指定平台都能真实按条件搜索，用户能分清成功、空结果和失败，能对同一岗位查看各来源，并完成收藏或 JD 保存。当前没有使用时长、匹配准确率或录用率基线，不承诺这些指标。

## 2. 目标与非目标

**本次覆盖：** 单组关键词、单个具体城市或“所有”城市、可选来源的后端搜索；分批加载与单站重试；职位概要、四项筛选、保守去重；详情和原链接；本机收藏；保存到现有资料库“目标 JD”。选择“所有”时不附加具体城市条件，结果保留岗位实际城市。这些能力共同构成首版闭环。

**明确不做：** 前程无忧及其他新来源、多城市、多组搜索方案、关键词自动扩展、完整搜索历史、后台定时刷新、消息提醒、不感兴趣列表、自动投递／打招呼／代聊、简历匹配评分、岗位诊断和模型调用。原有诊断或面试能力不因本轮被删除，也不新增从搜索到这些功能的联动。

**交付边界：** 本轮只沉淀需求与修正调研。下一阶段先验证三站搜索、翻页和详情，再安排完整功能开发。工具选型、接口、存储结构与页面布局在技术和界面设计阶段落实，不把本文当作已有实现。

## 3. 目标用户与使用场景

| 角色 | 使用范围 | 典型场景 |
|---|---|---|
| 本机求职用户 | 输入条件、浏览筛选、查看详情、收藏和保存 JD；不承担招聘平台账号配置 | 输入“Java 后端＋深圳”，比较三站机会，收藏有兴趣的岗位，将选定来源的 JD 保存到资料库 |
| 开发者／维护者 | 配置并维护后端所需 API 凭据、Cookie 或浏览器会话，处理失效和平台适配问题 | 某来源失效后修复访问配置，让用户再次搜索；不要求建设面向用户的账号管理后台 |

“Java 后端＋深圳”是用户确认的接入验收样例，不代表其个人求职意向。首版延续本机使用范围，不新增多人共享招聘账号或公网托管服务。

主要路径是：设置条件 → 搜索并查看来源状态 → 筛选与展开重复岗位 → 查看来源详情 → 收藏，或预览编辑 JD 后保存。收藏与 JD 保存互相独立，可以只做其中一个。

## 5. 详细行为与验收标准

验收编号中的 AC 表示需要证明的可观察行为，表格本身不是通过证据。实际结果见验证记录；页面与接口的当前接线见 [技术契约第7节](TECH_DESIGN.md#7-岗位搜索技术契约2026-10-23)，资料库继续复用现有业务能力。

### 5.1 V6-REQ-01：设置和记住搜索条件

用户填写一段非空岗位关键词、选择一个具体城市或“所有”、勾选至少一个来源，再点击搜索。首次默认勾选 BOSS、猎聘、智联；后续记住最近一次关键词、城市和来源选择。关键词按用户输入搜索，不自动生成近义词或替换为其他岗位；具体城市必须作为地域条件处理，“所有”明确表示不附加具体城市条件，不能仅把城市名拼入关键词便声称城市搜索成功。

重新进入页面后只恢复条件，等待用户主动搜索；不自动恢复旧结果为当前结果，不保存多次搜索历史。修改输入不会自动发起外部请求。

| 验收编号 | 给定—操作—预期结果 | 检查入口 |
|---|---|---|
| V6-AC-101 | 给定首次使用，输入“Java 后端”、选择深圳并发起搜索，则默认向三个来源传递同一关键词和城市含义；不扩展关键词。 | 搜索表单、后端来源调用与真实结果抽查 |
| V6-AC-102 | 给定关键词空白、未选城市／“所有”或未选来源，点击搜索则说明缺少的输入，不发起搜索；修正后可以继续。选择“所有”时请求不绑定具体城市。 | 表单与服务端输入校验 |
| V6-AC-103 | 给定此前已搜索并收藏／保存 JD，重新进入页面则恢复最近条件，等待主动搜索；不恢复搜索历史，已有收藏和 JD 仍可查看。 | 页面重进、收藏列表和资料库 |

### 5.2 V6-REQ-02：后端多源搜索

**访问责任。** 前端把条件交给本项目后端，由后端调用适合的 API、命令行工具或后台浏览器，再返回统一结果。允许组合多个开源工具并补充必要适配，不要求单一依赖覆盖三站。首版不依赖付费数据 API；免费方案不能满足时应报告并重新讨论，不擅自购买或改用付费服务。

开发者负责后端访问配置、登录态续期和必要的人工验证。用户无需登录招聘平台、导入 Cookie 或处理验证码。配置不存在、过期、遇到验证或限流时，受影响来源显示不可用及不含敏感信息的原因，并提供重试；开发者处理后才能恢复。“用户无感”指不承担访问配置工作，不代表故障不可见或永不需要维护。

**数量与顺序。** 每站首批最多获取 20 条来源岗位，平台可返回少于 20 条。结果超过 20 条后按每页 20 条分页展示；用户翻到已获取范围之外的页码时按需获取下一批，每次搜索累计最多获取每站 100 条来源岗位。折叠去重后可见条数可能更少，不能为凑齐数量无限补抓。后续结果仍逐来源处理，已结束或达到上限的来源不继续请求；源站分页大小的适配及请求限制由技术方案落实。

各站先返回先展示。保留每站原有结果顺序，在已有结果中交替展示来源；未返回的来源不阻塞其他来源。默认排序不表示本产品给出统一相关性评分，也不推断哪个平台的第一条比另一个平台更合适。

**任务控制。** 某站失败保留其他结果，也保留该站之前已成功获取的批次；可仅重试失败来源。停止本次搜索后保留已返回结果，迟到响应不再追加。开始新搜索时替换旧结果，旧任务不得写入新列表；收藏及 JD 不受影响。重新开始搜索、翻到后续页触发的按需获取和单站重试都必须区分任务身份，避免重复点击造成重复结果。

| 来源／任务状态 | 展示与后续操作 |
|---|---|
| 未选择 | 不请求该来源，不把它计为失败或空结果 |
| 查询中 | 显示该站正在搜索，已返回岗位可以浏览；可停止本次搜索 |
| 成功且有结果 | 展示结果；超过20条时分页，翻到已获取范围之外且未达上限时按需获取下一批 |
| 成功但无结果 | 明确该站查询成功但本次没有岗位；可以修改条件搜索 |
| 不可用／失败 | 显示来源、简明原因及重试入口；配置或验证问题由开发者处理 |
| 已停止 | 保留停止前结果，不接收该任务迟到数据；可重新发起搜索 |
| 已结束／达到上限 | 说明已获取范围；不声称已经取得平台全部职位 |

| 验收编号 | 给定—操作—预期结果 | 检查入口 |
|---|---|---|
| V6-AC-201 | 给定可用后端配置，对三站分别搜索“Java 后端＋深圳”、加载下一批并打开详情，则各站能取得相关真实岗位、正确城市含义、具体职位链接和可识别的正文；不能只返回推荐页或重复第一页。 | 三站接入探针、源站对照及详情链路；是完整开发前的门槛 |
| V6-AC-202 | 给定三站响应速度不同，发起搜索则先展示已经返回的结果，并显示其他来源仍在处理；结果保留站内顺序、按来源交替组织。 | 可控延迟的适配测试和页面 |
| V6-AC-203 | 给定各站有足够结果，首批各站最多 20 条；结果超过20条后分页，翻到已获取范围之外按需获取下一批，累计各站不超过 100 条，达到上限显示提示；实际不足时不补造岗位。 | 分批结果、分页、来源计数与页面 |

| V6-AC-205 | 给定未配置、凭据失效、验证或限流，用户搜索则看见该来源不可用及原因，不要求用户登录或处理验证码；前端响应、页面与普通日志不泄露凭据。 | 后端错误映射、页面及脱敏日志 |
| V6-AC-206 | 给定正在搜索，停止后已返回结果保留且迟到响应不追加；发起新条件搜索后旧响应不混入，收藏和 JD 保持。 | 可控并发响应、停止／新搜索及持久记录 |

### 5.3 V6-REQ-03：概要列表与筛选

概要包括职位名称、公司、城市／地点、岗位类型、薪资原文、经验要求、学历要求、来源和获取时间；源站提供发布时间时另行标注，不能把获取时间当发布时间。获取不到的内容明确为未知或未获取，不用零薪资、“不限”或当前日期代替。

筛选仅作用于**本次已获取的结果**，界面应说明这一范围。选择搜索来源决定向哪些站发请求；结果来源筛选只是缩小已有结果，两者不能混淆。加载新批次后继续应用当前筛选。

| 筛选项 | 判定口径 |
|---|---|
| 来源平台 | 只考虑已获取且属于所选平台的来源记录；不会因此补查之前未搜索的平台 |
| 岗位类型 | 首版统一为“日常实习”“暑期实习”“正式岗位”三类；来源明确标注或文本足够明确时才归类，无法可靠判断时保留“未知类型”，可选择隐藏。暑期实习优先于一般实习匹配；不把校招、应届生或兼职等模糊词自动等同于正式岗位 |
| 薪资 | 按月薪区间有交集判定，例如选择 20～30k 可保留 15～25k。保留原文；13 薪等薪数单独展示，不据此抬高月薪。不能可靠转换为同一月薪口径时作为未知，不能擅自假设发薪月数 |
| 经验 | 筛的是岗位发布的经验要求，保留原站区间／类别含义；不是让用户输入自身经验后计算个人适配度 |
| 学历 | 筛的是岗位发布的学历要求，保留原文含义；“本科”不自动等于用户已符合学历要求 |
| 未知值 | 缺失、面议或无法解释的条件默认保留并标注，可选择隐藏。“未知”和原文明确“不限”不同；一个字段未知不能抵消另一项明确不符 |

具体筛选控件、经验／学历显示选项及平台枚举对应在后续设计中列明；不得把原文宽区间强行映射成更精确要求，或静默改变上述业务含义。

| 验收编号 | 给定—操作—预期结果 | 检查入口 |
|---|---|---|
| V6-AC-301 | 给定有完整字段、缺失字段和源站发布时间的记录，展示概要则原值与未知标识可区分，获取时间与发布时间不混用。 | 列表与适配后数据 |
| V6-AC-302 | 给定 15～25k·13薪及 8～12k 岗位，筛选 20～30k 则前者保留、后者排除；13 薪单独显示，不修改月薪区间。 | 筛选逻辑与列表 |
| V6-AC-303 | 给定薪资面议、字段缺失和非月薪且无法可靠转换的记录，设置筛选时默认保留相应未知项；隐藏未知后排除。某来源其他条件明确不符时仍排除。 | 筛选组合与未知开关 |
| V6-AC-304 | 给定已获取若干岗位，按来源、经验和学历筛选，则按岗位要求过滤并标明仅筛选已获取范围；翻到后续页触发新批次后，新记录适用相同条件。 | 筛选区域、分页与结果计数 |
| V6-AC-305 | 给定来源明确标注日常实习、暑期实习、正式岗位和无法判断类型的岗位，按岗位类型筛选时只保留同一来源同时满足的记录；未知类型默认保留，关闭未知后排除。 | 类型归类、筛选逻辑与列表 |

### 5.4 V6-REQ-04：去重与来源保留

同一平台的同一职位只显示一次，跨页、重试或重复返回不能造成副本。身份需要同时包含平台与该平台职位身份；不同平台即使 ID 相同，也不能视为同一记录。

跨平台只有明确为同一岗位时才折叠，展开后仍能查看各来源详情和原链接。仅岗位名称相似、公司同名或城市相同不足以证明重复；不同部门、地点或招聘要求不能因为相似而丢失。具体识别算法在技术方案中确定，首版不使用模型判断。

折叠是展示分组，不是把来源字段混成一份记录。薪资、经验、学历或正文冲突时保留各站原值并提示差异。筛选必须在**单个来源记录上同时满足全部条件**，再决定该组是否出现；未知字段按 V6-REQ-03 处理。列表使用满足筛选的一个来源作为代表，明确其平台，详情仍可切换其他来源，不把其他来源伪装成也已满足筛选。

| 验收编号 | 给定—操作—预期结果 | 检查入口 |
|---|---|---|
| V6-AC-401 | 给定同站同岗跨页重复，以及不同站使用相同 ID，搜索或重试后前者只显示一次，后者保持独立来源身份，不相互覆盖。 | 去重逻辑、分批聚合与列表 |
| V6-AC-402 | 给定有明确同岗证据的多站记录和仅名称相似的记录，前者折叠且可展开全部来源，后者独立保留；各来源链接和正文不丢失。 | 分组结果、详情切换与样本核对 |
| V6-AC-403 | 给定同岗的 BOSS 来源薪资符合但学历不符，猎聘来源学历符合但薪资不符，同时设置这两项筛选则该组不因拼接字段而通过；若一个来源同时符合，则展示该来源并保留差异提示。 | 跨来源组合筛选与列表代表项 |

### 5.5 V6-REQ-05：详情与原岗位

用户可从概要进入详情，查看已获取内容、来源、获取时间和原岗位链接。折叠岗位可以切换来源，正文及字段随来源切换。打开原链接应指向对应的具体职位，不能用平台首页冒充；源站是否继续要求登录或职位是否下架，以原站实际行为为准，本应用不承诺外站免登录。

只有概要的记录也可展示，标注“详情未获取”；查看时再尝试读取。读取失败保留概要并说明原因，允许重试、收藏已有内容或跳转原站。保存 JD 时没有正文则需用户补充，不能把简短概要当成完整 JD。

临时访问失败、验证码和搜索结果中消失都不足以证明下架。原站已不可读时仍可查看本地已保存内容，但须保留获取时间，不能称为当前实时岗位信息。

| 验收编号 | 给定—操作—预期结果 | 检查入口 |
|---|---|---|
| V6-AC-501 | 给定多来源岗位，打开详情并切换来源则字段、正文和具体原链接与所选来源一致；点击链接访问该职位，不被替换为平台首页。 | 详情、链接目标及源站核对 |
| V6-AC-502 | 给定只有概要的记录，打开详情会尝试读取；失败时保留概要、标注缺失并提供恢复入口，仍可收藏或查看原岗位。 | 详情成功／失败分支 |
| V6-AC-503 | 给定网络失败或需要验证，查看详情不自动标成下架；给定原站已失效的收藏，仍可阅读本地快照及原获取时间。 | 状态映射、原站失效样本及收藏详情 |

### 5.6 V6-REQ-06：本机收藏

用户可以收藏或取消收藏，在本机收藏列表中查看。收藏保留操作时**已经获取**的岗位概要、详情、各来源链接和获取时间；未获取的正文仍标缺失。原站变化、重新搜索及之后读取到新正文，都不自动覆盖收藏快照。

重复收藏同一来源岗位不产生多份记录。跨站已确认同岗的收藏保留来源关系，不能因列表分组变化混淆身份。收藏与 JD 不是同一份内容：收藏不自动写入资料库，取消收藏不删除已保存 JD，编辑或删除 JD 也不改写收藏快照。

| 验收编号 | 给定—操作—预期结果 | 检查入口 |
|---|---|---|
| V6-AC-601 | 给定一个岗位或明确同岗分组，收藏后刷新页面及重启应用，仍能从收藏列表读取当时已获取的内容、来源和时间；重复收藏不新增副本。 | 收藏入口、本机持久化与恢复 |
| V6-AC-602 | 给定已收藏岗位，源站正文变化、下架或下一次搜索结果不同，本地收藏仍保持原快照；缺失字段不因新请求被静默覆盖。 | 收藏快照与变化后的搜索／详情 |
| V6-AC-603 | 给定岗位已收藏且保存了 JD，取消收藏则收藏列表移除该项，JD 保留；编辑或删除 JD 不删除或改写仍存在的收藏。 | 收藏列表与资料库交叉核对 |

### 5.7 V6-REQ-07：保存 JD

保存入口针对一个具体来源。多个来源时先选来源，然后预览并允许修改资料名称、正文，再确认存入现有资料库的“目标 JD”；不能将多站正文自动拼接，也不调用模型生成或补全正文。只有一个来源时直接预览该来源。

名称必填、最多 120 字符；正文必填、最多 24,000 字符。空白不算有效内容，超限提示用户修改，不自动截断。正文未获取时允许手工补充；保留来源关联以及正文经用户补充／编辑的事实，不能将补充内容称为原站全文。取消保存不写入资料，失败保留本次输入供重试。

同一“平台＋来源职位身份”已有有效 JD 保存关联时，入口显示“查看已保存 JD”，不重复新建，也不覆盖用户在资料库中的后续编辑。不同来源可以分别保存，即使展示时折叠为同一岗位。重复点击或请求重试不得产生多份资料。已关联 JD 被删除后，从仍保留的岗位记录可重新保存；不自动恢复已删除资料，也不凭空恢复未收藏的旧搜索结果。

需求冻结时，资料库已有 JD 增查改删和 120／24,000 字符限制，招聘来源元数据和来源级保存幂等属于本次新增行为；2026-10-24 已接入软件实现，证据另见验证记录。依据：[MaterialService](../../../../backend/src/main/java/cn/interview/service/material/MaterialService.java)、[Material 模型](../../../../backend/src/main/java/cn/interview/entity/Material.java)、[资料库页面](../../../../frontend/src/pages/material/Materials.vue)。这里的保存上限不应误写为岗位诊断等消费入口的 10,000 字符限制，本轮不改变这些消费入口。

| 验收编号 | 给定—操作—预期结果 | 检查入口 |
|---|---|---|
| V6-AC-701 | 给定多来源岗位，选定一个来源并编辑预览后确认，则资料库增加一份类型为 JD 的资料，名称和正文与确认内容一致，来源可追溯；取消则不创建。 | 保存预览、后端写入与资料库 |
| V6-AC-702 | 给定缺失正文或空白名称／正文，保存时提示补充；给定名称超过 120 或正文超过 24,000 字符，提示修改且不截断。符合边界的非空输入可以保存。 | 前后端输入校验与预览 |
| V6-AC-703 | 给定同一来源岗位已保存 JD，重复点击或重试不产生副本，显示已保存资料入口；用户已修改的正文不被新搜索覆盖。另一来源可单独保存。 | 来源关联、并发提交与资料库记录 |
| V6-AC-704 | 给定关联 JD 已被用户删除，从仍保留的岗位记录再次保存则可新建；给定保存失败，预览输入保留，不错误显示成功。 | 删除后保存、失败恢复与资料库 |
| V6-AC-705 | 给定一次搜索、收藏及 JD 保存的完整流程，未发生模型调用、岗位诊断、招聘沟通或投递，也未自动为未选岗位创建 JD。 | 外部调用记录、业务请求及资料库变化 |

## 7. 限制、非功能要求与验收边界

### 7.1 接入验证先于完整开发

三个指定平台都必须通过 V6-AC-201 的基础能力核验。一个平台永久不可用、只返回固定推荐、城市没有生效、无法翻页或始终无法读取正文，都不能靠“允许部分失败”获得通过。个别职位详情缺失可以按 V6-AC-502 降级，但不能将整个来源无详情能力视为已支持。

下一阶段用“Java 后端＋深圳”执行三站的有界真实搜索、翻页和列表到详情读取，对照原站核对来源身份、地域、内容与具体链接，记录固定工具版本、访问方式、获取时间和失败情况。还需检查条件确实传入平台，避免把固定结果当搜索。验证所需请求数、超时、并发和停止限制由技术方案给出；当前没有经实测确认的耗时承诺。

未达到门槛时，先报告具体缺口，讨论新的接入方案或明确调整范围，不静默降为两站、不用模拟数据或手工导入替代真实聚合。接入证明只覆盖实际测试条件，不能保证平台长期稳定或覆盖全站。
