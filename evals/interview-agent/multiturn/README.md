## 2. 材料职责与现有事实

- `cases.json`：合成对话及评阅预期的唯一数据源。`dialogue` 保存普通可见信息，`oracle` 保存评阅规则；后者禁止发送模型。
- `CASES.md`：从上述 JSON 生成的人类阅读视图，包含 12 个剧本、消息身份和逐例验收表；案例改动应先改 JSON，再同步生成视图。
- 本文件：本次确认边界、验收标准、原发现批协议与结果，以及第 12 节独立改进结果。案例预期与运行记录分开，不能把预期填写成成功记录。
- [原固定评测](../README.md)及其 24 例、基线快照、脚本、人工评分和账本继续由原入口维护。

每个 `dialogue.turns` 条目包含问题、回答和稳定的消息、主问题身份；`oracle.checkpointTurn` 指向唯一关键轮，`oracle.evidence` 用回答消息 ID 与逐字短引定位原答。`oracle.stateExpectations` 只表示评阅者期待的处理方式，不规定必须新增哪些存储字段。案例标题、情境分类和普通背景说明只帮助读者理解，不额外发送模型；实际请求仅使用第 4 节白名单。

`cases.json` 和 `CASES.md` 保留素材准备时的快照，其中“未执行”是准备时占位，不追踪后续运行。真实执行状态以本文件当前状态、共享账本和对应本机评阅包为准；不能改写案例预期来迁就输出。

当前生产共用链路为 `InterviewService` → `InterviewModelClient` → `OpenAiJsonClient`；真实请求经过生产校验、代次保护和整场快照保存。综合与快速均使用 `/api/interviews`，旧地址仅是兼容别名。当前代码核验入口为 [Service](../../../backend/src/main/java/cn/interview/service/interview/InterviewService.java)、[客户端](../../../backend/src/main/java/cn/interview/client/interview/InterviewModelClient.java)和[配置](../../../backend/src/main/resources/application.properties)。

V4 真实固定评测仍保留 3 次尝试、2 项结构通过、1 次网络或等待失败的停批记录，未形成六例完整基线。随后独立的 30 秒追问校准是一个成功样本，未计入原/新策略基线；详见 [V4 验证记录](../../../docs/vibe/releases/v4/VERIFICATION.md)。本任务不修改其状态、失败记录、预算或人工关卡。

## 3. 验收标准

以下是验证时应检查的标准。首批固定输入已有真实输出，人工质量判断与生产连续场次验收尚未完成。

| 编号 | 通过标准 | 必须保留的反向检查 |
|---|---|---|
| AC-CONT-01 | 后续提问不再要求复述已充分说明的同一目的 | 同主题尚未验证的新边界仍可深入，不能一律换题 |
| AC-CONT-02 | 后续使用明确更正后的经历、职责、背景和指标，并能定位更正前后原答 | 不自动接受更正后的客观技术主张，不把更正解释成诚信问题 |
| AC-CONT-03 | 两处未解决冲突都能回到原话，下一问中立核实时间、范围、条件或职责 | 已给出充分解释的差异不继续追究；无依据不确定判错 |
| AC-CONT-04 | 第 5 轮决策尊重第 1 轮中仍适用的具体限制 | 不引用无关历史，不补造未说过的指标、权限或经历 |
| AC-CONT-05 | 明确区分假设、候选人经历陈述、模型观察和可核验技术依据 | 假设方案不升级为真实上线经历，短引存在不等于语义正确 |
| AC-CONT-06 | 完整场次只继承本分支真实生成、通过校验并实际保留的状态 | 失败、超时、迟到、重复提交不重复写入；模型动作与实际动作分开记录 |
| AC-CONT-07 | 同场刷新与重启后状态和原答关系可恢复，新场保持隔离 | 不回填已结束历史、不串用同 ID 的其他来源场次；进行中不泄露内部诊断 |
| AC-CONT-08 | 每个拟修复问题都有原始失败输出及人工可核对的依据，改后逐项改善 | 正常深挖、技术核验、无关信息排除和已澄清事项均无关键回退；阻断项不能被平均分抵消 |

每个关键点记录动作是否允许、必需行为、禁止行为、相关短引和人工理由。状态使用“未执行、通过、失败、不适用、无法判断”；不适用和无法判断都必须给出原因。Agent 初评与人工结论分别保存，人工署名和确认不能由 Agent 代填。

人工反馈可直接在聊天中给出，无需用户检查代码、读取原始 JSON 或操作评分文件。Agent 负责提供“必要上下文、实际追问、推荐判定及理由”，并准确转录用户明确给出的结论；尚未得到的逐例结论保持未确认，不把测试授权或 Agent 初评代填为人工意见。

## 4. 第一层：固定历史关键点

### 输入准备

每例先观察前 5 轮已提交问答，在第 5 次回答之后生成一次 FOLLOWUP 决策。历史问题是合成场景中的主问题，不表示生产模型曾生成过这些问题；`followUpCount=0`，避免服务端两次追问上限掩盖策略判断。综合样例的观察窗口位于 `TECHNICAL`，不触发反问回应或阶段时间收尾；快速样例不增加四阶段控制。五轮是本组观察窗口，不能宣称完整综合面试只有五轮。

拟定的输入白名单：

| 输入字段 | 来源与限制 |
|---|---|
| `role`、`level`、`sessionType` | 仅取 `dialogue`；快速不传私人简历、JD 或项目创建资料 |
| `summary`、`jd` | 固定为空的普通准备字段；不由人工验收预期反推摘要，`jd` 为空字符串 |
| `messages`、`currentQuestion`、`answer` | 按 `dialogue.turns` 生成截至关键轮的消息；问题、回答和主问题 ID 对应，当前问题为末轮问题 |
| `followUpCount`、`strategyVersion` | 分别固定为 0、1；用于当前专业诊断协议，不额外调用 PLAN、ANALYZE 或 REVIEW |
| `sources` | 仅按声明的 `sourceIds` 复用 [已冻结来源](../sources.json)的公开字段；空来源不补造技术依据 |
| 综合阶段字段 | 综合才传 `experienceVersion=1`、`stage=TECHNICAL`、`reduceFollowups=false`、空的假设项目 `mainProject={hypothetical:true,brief:""}`；不从人工预期反推项目，不启用计划完成协议 |
| `diagnostics` | 没有对应历史真实输出时为空数组，来源标记在请求外保存为“历史诊断未生成” |

首批不为填满历史状态而伪造诊断，也不用 Mock、人工正确答案或 `oracle.stateExpectations` 代替历史输出。空历史诊断下发现的问题先记为“候选问题”；它不能单独证明带有真实连续诊断的生产 V4 存在同样缺陷。冻结业务改进前，还需用适用的生产状态复核。

执行输入固定 `summary={}`，与生产准备后的摘要存在差异；不传 `plannedQuestionCount` 或 `remainingStageQuestions`，不检验整场规划完成协议。素材未达到正文节选阈值时原文完整发送；达到 94,000 个 Java 字符单位时工具拒绝试跑，不仿写裁剪并冒充生产节选。以上差异写入运行协议和逐项输入摘要。

请求构造禁止直接序列化整个案例。`title`、`scenario`、`oracle`、合理/禁止行为、正确事实、更正关系、缺陷标签和评分规则仅供评阅。对早期关键点不得提前传入后续轮次。

固定历史材料只提供一个观察机会。例如模型合理选择 NEXT，却没有引用历史纠正，不能据此认定它已经正确保存全部信息。各子项分别判定；证据不足记为无法判断，必要时留待动态层复核，不能为增加可观察性额外请求或把整例自动算作通过。

### 对照身份

第一批只计划观察当前策略，每例一次，最多 12 次，先找问题。候选策略目前不存在，未安排其请求。后续配对须固定同一组原始对话、来源、岗位与阶段条件；先对原始输入保存共同摘要，再分别记录各策略的实际派生输入摘要、Prompt 和实现摘要。

若只是改提示词，配对的模型输入应完全一致；若改上下文构建，原始可见对话必须一致，派生输入可以按策略不同，但需逐项记录差异，不能声称最终输入完全相同。不得为此放宽原 24 例运行器的混组检查。

## 5. 第二层：实际连续场次

这一层尚未安排执行次数或实现。后续从已暴露问题的剧本中选择轨迹，通过同一生产 Controller、Service、校验和存储路径，观察实际问题、回答、诊断、推进和备用行为。准备、开考、阶段切换、结束与复盘等调用若有发生，全部另列次数和预算；不能隐含在 12 次 FOLLOWUP 中。

每个策略只继承自身分支真实产生、验证后实际保留的状态；不得把人工正确记忆灌入下一轮，也不能手动修好记忆后继续并计为模型成功。`action` 与 `effectiveAction` 分开，澄清是否完成以实际问答和回答证据为准，不能因模型曾计划澄清就将事项关闭。

实际问题可能与固定剧本不同。此时依据预先声明的候选人背景回答实际问题，只允许使用该节点已公开的信息；不能为了到达第五轮而把不相干的预写回答硬接上。无法接续、需要额外轮次或人工调整时记录分支偏离/人工干预并暂停该轨迹，重新安排所需预算。两策略轨迹不同，不得冒充相同输入的逐轮配对。

实际场次另检查：同场刷新、重启恢复、两场隔离、重复请求幂等、取消/超时后的迟到结果失效、实际动作与候选状态一致、进行中隐藏内部诊断，以及旧项目/简历入口的必要兼容。这些离线或软件行为检查不替代真实专业性判断。

| 项目 | 已确认规则及当前状态 |
|---|---|
| 类型 | 执行时策略快照的发现试跑，每例第 5 轮一个关键点；仅 FOLLOWUP。当前源码已有变化，结果适用身份见第 10 节 |
| 固定顺序 | `CONT-C01`、`CONT-Q01`、`CONT-C02`、`CONT-Q02`，依此交替至 `CONT-C06`、`CONT-Q06`；停批后保留余项未执行，不跳过失败继续下一例 |

| 调用方式 | 每次只有一次模型请求，无自动重试、无隐式分析/规划/复盘；未配置密钥时明确失败，不转 Mock |
| 停批 | 第一次网络失败、非法/不完整 JSON、截断或机械结构校验失败即停；语义质量问题保留原文用于逐例分析，不伪装为网络失败 |

| 模型与身份 | 执行前冻结请求模型、脱敏服务身份、温度、思考配置、输入/来源/Prompt/校验器/执行器摘要；响应后记录实际返回模型，后续配对逐例核对，缺失或不符不得混组 |

| 数据 | 只发送已检查的合成问答及固定公开短引；不读取个人场次、私人资料或密钥到公开材料 |
| 结果 | 逐次保留原始输出、结束原因、结构检查、请求和实际动作、传输/业务耗时、输入/输出/合计 Token、未知用量标记、备用触发及原因 |

12 次预算仅能支持首批发现。对成功记录按相同身份复用；失败任务不自动重试。参数、策略、输入或工具变化后先区分实验身份，不拼接不可比结果；新身份仍累计消耗同一首批 12 次总上限，不会重置预算。未知用量不填零，未知单价不估算费用；小样本先列逐次数据，不用少量成功样本声称总体稳定性或性能分位数。

原 [运行器](../../../scripts/interview-agent-eval.py)保持原样，继续只支持原 24 例。新 [发现运行器](../../../scripts/interview-continuity-eval.py)通过只读导入复用原单次传输、严格 JSON 和机械校验函数，分别绑定两个脚本摘要；不改变 V4 旧协议。它只支持本组固定历史发现，不支持动态连续场次或双策略质量验收。


1. 打开本机 `http://127.0.0.1:5173/`，确认右上角显示模型已配置，资料和历史仍在。
2. 点击“快速练习”，选择“Java 后端工程师”、5 道主问题，再点“开始快速练习”。若希望项目上下文更集中，可改走“综合面试”，选择“不限时训练”，在“简述或补充主项目”声明合成的导入或任务调度练习；点击“进入深度准备”，核对摘要后点“确认无误，直接开始”。
